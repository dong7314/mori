# Hermes 기능과 모리 PoC 확장

확인일: 2026-09-16. Nous Research의 공식 Hermes Agent 문서를 기준으로 정리했다. 아래의 모리 UI와 기능 조합은 제품 설계이며, Hermes의 기본 화면을 그대로 제공하는 것이 아니다.

## 확인한 기능 → 모리에서 풀어낸 경험

| 공식 기능 | 모리에 맞는 활용 | 이번 PoC |
| --- | --- | --- |
| [Persistent Memory](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory): 세션 간 핵심 정보와 사용자 선호 저장, 과거 세션 검색으로 보완 | 여행 취향, 설명 방식, 특별히 챙길 점을 기억하고 수정하기 | 취향 편집·로컬 저장. 브리핑과 새 여행 결과 설명에 반영 |
| [Skills](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills): 필요한 절차를 불러오고, 경험이나 자료에서 재사용할 스킬 만들기 | 반복하는 부탁을 ‘모리가 익힌 방식’으로 보여주기 | 주차 표시 규칙과 한 주 정리 제안. 자동 학습·실제 스킬 파일 생성은 미연결 |
| [Cron](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron): 일회성·반복 예약, 스킬 연결, 중지·재개·수정·즉시 실행과 결과 전달 | 아침 브리핑, 주간 회고, 여행 준비 확인 | 반복 요일·시간 저장, 다음 시각 계산, 일시 중지, 지금 미리보기. 브라우저 밖 예약 실행은 없음 |
| [Tools](https://hermes-agent.nousresearch.com/docs/user-guide/features/tools): 검색·브라우저·파일 도구와 작업 실행 | 여행 검색 → 일정 초안 → PDF·Excel 결과 | 여행·문서 요청과 결과 모음. 검색·파일 분석은 수행하지 않음 |
| [Voice Mode](https://hermes-agent.nousresearch.com/docs/user-guide/features/voice-mode): 음성 입력·전사·음성 응답, 플랫폼별 음성 상호작용 | 말과 글을 같은 대화에서 오가기 | 음성 체험 화면, 시작/종료, 전사 문장 편집, 같은 대화로 전송. 녹음·STT·TTS는 미연결 |
| [MCP](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp): 외부 도구 연결 | 외부 캘린더와 문서 저장소 연결 | 현재는 브라우저 내부 캘린더. 외부 계정·전송 없음 |

## 화면 구성

- **오늘**: 시간대별 첫 위젯, 하루 브리핑, 남은 일정, 모리가 반복해서 챙기는 일, 준비된 결과, 여행·문서·취향 진입점. 홈에는 채팅 내역이나 입력창을 다시 넣지 않았다.
- **어디서나 부탁하기**: 하단의 `말로 부탁 / 글로 부탁`. 대화 상세에서는 상단 전환 버튼으로 같은 대화를 유지하면서 입력 방식을 바꾼다.
- **음성 화면**: 입체적인 마이크, 시작 시 원형 빛과 파형, 편집 가능한 체험 문장. 종료하면 음성 말풍선과 결과 카드가 글 대화에 나타난다. 글 초안과 음성 초안은 따로 보존한다.
- **브리핑**: 현재 저장된 일정·주차·메모·취향으로 한 장을 만든다. 한 주 정리는 오늘을 포함한 7일의 일정·메모를 모은다. 결과는 홈에서 다시 열거나 원문을 대화에 연결하고 인쇄 기능으로 PDF 저장할 수 있다.
- **반복해서 맡긴 일**: 모리의 제안을 열어 시간·요일을 확인하고 켜거나 잠시 쉬게 한다. 자연어로 변경을 부탁하면 저장 전 제안으로 표시하고, 기존 설정은 사용자가 저장할 때 바꾼다.
- **알림함**: 실제로 대화에서 만든 여행의 캘린더 반영 요청과 주간 노트 제안을 표시한다. 승인한 여행의 결과는 해당 여행을 만든 대화에 기록한다.
- **모션**: 카드 등장, 카드 반응, 마스코트 움직임, 입력 모드 전환, 음성 파형, 브리핑 준비 단계, 메시지 등장. `prefers-reduced-motion`에서는 움직임을 멈춘다. 자동 위젯 갱신 때는 화면 진입 애니메이션을 재생하지 않는다.

## 실제 제품에서 별도로 구현할 부분

1. **모리 API 계층**: UI의 대화·작업·결과 ID를 Hermes 세션·스킬·예약 작업과 연결한다. 도구 호출의 중간 상태는 프론트에 안전한 진행 정보로 전달한다.
2. **사용자 격리**: 무료 사용자도 기억·세션·파일·예약·인증 정보를 사용자별로 분리한다. 공용 실행 자원을 쓴다고 기억까지 공유하지 않는다. 공식 메모리 문서는 동일 Hermes home을 여러 에이전트 프로세스가 공유하지 않도록 설명한다. 유료 전용 Pod의 CPU·메모리 제한과 별도로 저장소·권한 경계를 설계해야 한다.
3. **앱과 위젯**: Hermes의 예약 실행 결과를 받아 모리 서버가 표시할 카드와 갱신 시각을 관리한다. React WebView 브리지, OS 위젯·푸시·알람·백그라운드 권한 처리는 모리 모바일 앱의 몫이다. Hermes 자체 기능이라고 가정하지 않는다.
4. **음성**: 웹·앱 녹음 → 전사 → 동일 대화 전송을 연결하고 필요하면 음성 응답을 추가한다. Hermes 문서의 로컬 STT 선택지를 검토할 수 있지만, 3090에서 LLM과 동시에 운영할 때의 메모리·지연은 별도 측정한다.
5. **학습과 실행의 구분**: ‘기억한 사실’, ‘재사용할 절차’, ‘예약할 작업’을 분리한다. 여행의 캘린더 반영 등 사용자가 결정할 행동은 작업 내용과 대상을 보여준 뒤 실행한다.

## 다음 확장 후보

- 여행 출발 전 날씨·예약·준비물을 다시 확인해 변경된 점만 알려주기: 검색 + 예약 실행 + 원래 여행 대화 연결.
- ‘지난번 가족 여행 문서’처럼 기억으로 결과 찾아오기: 세션 검색 + 결과 파일 보관함.
- 통화나 음성 메모에서 일정·할 일 후보를 추출해 한 번에 검토하기: 전사 + 도구 실행 + 승인.

이번 변경은 위 연결을 검토할 수 있는 HTML·JavaScript·SCSS PoC이며, Hermes·LLM·검색 API·외부 캘린더를 설치하거나 연결하지 않았다.
