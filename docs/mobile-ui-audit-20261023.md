# 모바일 화면 점검 및 개선

2026-10-23 · `poc` 브랜치

ego-browser에서 다섯 탭과 상세·입력 화면을 직접 조작해 확인했다. 기존 카드 그래픽과 카드 확장 전환은 유지하고, 모바일에서 정보보다 안내 문구가 크게 보이거나 조작 후 흐름이 끊기는 부분을 정리했다.

## 변경 내용

| 영역 | 발견한 문제 | 변경 |
| --- | --- | --- |
| 대시보드 | 빈 상태와 인사말이 첫 화면을 크게 차지함 | 인사말을 한 줄로 정리. 시간별 카드와 저장한 결과에 집중하고 빈 상태는 작은 안내 영역으로 축소 |
| 대화 | 새 대화 안내가 기록보다 먼저 크게 보임 | 대화 기록과 검색을 우선 배치. 작성 중인 초안이 있을 때만 이어쓰기 표시 |
| 기능 | 카드 높이와 반복 설명 때문에 목록 탐색이 길어짐 | 그래픽을 유지하면서 카드 높이·문구·간격 조정. 내 기능 추가도 간결한 행으로 통일 |
| 마이 | 모바일 간격을 조정하면서 기존 항목이 제거되거나 로그인 후에만 보이게 바뀜 | 사용자 요청에 따라 기존 요금제 소개 카드·사용자 정보·사용자 정보 수정과 보조 문구를 복구. 비로그인 상태에서도 계정 메뉴를 표시하며 선택 시 로그인 안내로 연결 |
| 기록 검색 | 검색어를 지우기 어렵고 결과가 없을 때 복귀 동작이 부족함 | 검색어 지우기 버튼과 빈 결과 안내 추가. 입력 노드를 유지해 한글 조합과 포커스 보존 |
| 메모 삭제 | 삭제 후 보관함까지 닫혀 탐색 흐름이 끊김 | 보관함에서 열었다면 삭제 후 목록으로 복귀. 되돌리면 현재 목록을 갱신 |
| 폼 오류 | 상단 저장 버튼을 누른 뒤 오류가 화면 아래에 숨어 있음 | 해당 항목 아래에 오류를 표시하고 포커스·ARIA 설명 연결. 저장 실패는 폼 상단에 안내 |
| 좁은 상세 화면 | 320px에서 세로 배치 버튼이 기존 flex-basis를 높이로 받아 128px까지 커짐 | 세로 버튼의 flex-basis 초기화. 알림 버튼 높이를 약 51px로 복원 |
| 음성 입력 | 패널 뒤로 글자가 비치거나 빈 대화 제목이 반쯤 잘려 보임 | 음성 패널을 불투명하게 처리. 빈 대화 안내만 공간을 유지한 채 페이드 처리하고 닫으면 복원 |

공통 헤더·검색·터치 영역도 함께 정리했다. 내 기능 아이콘 선택은 320px에서 3열로 배치하며, 작은 화면의 알림 타이머 크기를 줄여 조작 버튼이 보이게 했다. 음성 입력의 하단 입력줄 위치와 실제 대화 내용은 유지한다.

## 대시보드 후속 정리

- ‘오늘의 약속’과 ‘최근 대화’를 홈에서 제거했다. 전체 일정·대화 기록은 하단 탭에서 확인한다. 시간에 맞는 일정 카드는 기존처럼 ‘지금 챙길 것’에 표시된다.
- 시간별 카드 다음에 ‘기록과 정리’를 배치하고, 맨 아래의 ‘모리와 더 편하게’ 영역은 사용자 요청에 따라 복구했다. ‘모리 둘러보기’와 ‘반복하는 부탁 만들기’로 연결된다.
- 대시보드에서는 종류별 탭 없이 메모·문서·실행 결과를 합쳐 최신순으로 최대 5개만 보여준다. 나머지 기록은 ‘전체 보기’에서 검색·필터와 상세 화면을 통해 확인한다. 실행 결과는 현재 내 기능의 결과이며 뉴스·주가 기록을 포함하지 않는다.
- 홈의 ‘전체 보기’를 누르면 보관함의 전체 기록이 열린다. 종류별 필터와 검색은 보관함 안에서 제공하며, 보관함의 선택은 홈의 최근 기록에 영향을 주지 않는다.
- 카드 하단의 중복 안내 행을 제거하고 좌우 탐색 아이콘을 통일했다. 시간 범위 메뉴는 선택 항목의 체크만 표시하며, 헤더 오른쪽 컨트롤은 13px·굵기 500으로 맞췄다.
- 미리 보는 하루의 시간 요약은 중복된 범위 문구를 덜고 시작·종료 시간과 ‘N개 항목’을 나란히 배치했다. 항목 수는 한 줄로 유지하며, 좁은 화면에서 자정을 넘는 긴 시간 범위만 줄바꿈한다.
- 시간 요약은 주변 카드와 같은 테두리·그림자를 사용하고 세이지 색은 옅게 남겼다. 별도의 강조색 윤곽은 제거했으며, 항목 수 역시 기본 글자색으로 맞췄다. 라이트·다크 테마의 기존 색상 변수를 공유한다.

## 확인한 동작

- 320·390·430px 모바일 폭에서 화면을 확인하고, 320·430·768px의 다섯 탭에서 문서·본문 가로 넘침이 없는지 측정했다.
- 라이트·다크 화면을 확인했다. 320×640에서 음성 입력 전후 입력줄은 `y=575`, 높이 `44px`로 동일했다. 음성 예시를 펼쳐도 같은 위치를 유지했다.
- 대화 초안 작성 → 닫기 → 다시 열기에서 입력 내용이 유지됐다.
- 기록 검색 → 빈 결과 → 검색어 지우기에서 입력 포커스와 필터가 유지됐다.
- 빈 메모 저장 시 오류 항목으로 이동하고, 입력을 수정하면 오류가 정리됐다.
- 메모 저장 → 삭제 → 보관함 복귀 → 되돌리기를 확인했다.
- 미리 보는 하루의 주차 카드 → 확장 상세 → 닫기에서 원래 카드로 포커스가 돌아왔다. 뉴스·주가 상세도 가로 넘침을 확인했다.
- 최종 `npm run build`, `npm run check`, `npm test` 통과. 전체 테스트 231개 중 이번에 추가한 8개는 폼 오류·포커스·ARIA 처리, 2개는 대화 진입 경로별 복귀·동작 줄이기 검증이다. 로컬 HTTP 서버가 필요한 테스트는 실행 환경의 포트 제한 없이 재실행해 통과했다.

브라우저의 모바일 화면 에뮬레이션으로 확인한 결과다. 실제 iPhone Safari의 키보드·안전 영역, 음성 인식, OAuth 로그인, 결제·백엔드 통신은 이번 점검에 포함하지 않았다. 점검에 사용한 미리보기 저장소는 작업 전 값으로 복원했다.

## 구현 위치

- `src/app-experience.js`: 화면 구성·문구, 검색, 메모 삭제 후 복귀, 폼 오류 연결.
- `src/form-feedback.mjs`: 필드별 오류 표시와 포커스·ARIA 정리.
- `styles/_mobile-refinement.scss`: 모바일 헤더·목록·폼·터치 영역.
- `styles/_sheet-content-system.scss`: 좁은 화면의 상세 버튼 높이 수정.
- `styles/_luminous-chat.scss`: 음성 입력 배경과 빈 대화 안내 전환.
- `styles/main.css`: SCSS 빌드 결과.

## 대화 진입 경로별 전환

- 대화 탭의 새 대화·작성 중인 대화·기존 대화는 일정 및 기능 추가 화면과 같은 오른쪽 진입, 오른쪽 복귀 전환을 사용한다.
- 하단 고정 입력창과 마이크는 기존 아래에서 올라오는 전환을 유지한다. 대화 탭에 있더라도 실제 누른 버튼의 위치로 진입 방식을 구분한다.
- 열린 채팅 안에서 새 대화를 시작해도 처음 진입 방향을 유지한다. 목록 갱신 후에도 원래 열었던 버튼으로 포커스가 돌아간다.
- 가로 진입에서는 배경을 어둡게 하는 효과와 세로 끌어내리기를 적용하지 않는다. 태블릿에서도 전체 화면으로 연결하며, 입력 내용과 음성 입력의 동작은 기존대로 유지한다.
- 모바일 390px에서 가로 진입·복귀, 하단 입력창의 세로 진입·복귀, 채팅 내부 새 대화, 기존 대화의 음성 입력을 펼친 상태에서 닫기를 확인했다. 768px 태블릿 화면과 동작 줄이기 설정도 확인했다.
- 빌드·문법 검사 및 전환·포커스·음성 세션 관련 테스트 79개 통과. 실제 기기의 소프트웨어 키보드 동작은 별도 확인 대상이다.

## 목록 높이와 텍스트 정렬 후속 정리

- 내 기능과 ‘새 기능 만들기’를 같은 목록으로 묶었다. 40px 아이콘, 12px 간격, 좌우 18px·상하 16px 여백을 공유한다. 실행 결과가 있는 기능도 요약 한 줄에 함께 표시해 행이 늘어나지 않는다.
- 대화 제목과 미리보기는 각각 한 줄로 표시하고 넘치는 부분은 말줄임한다. 모바일에서 미리보기를 두 줄로 늘리던 예외 규칙을 제거했다. 작성 중인 대화에도 같은 말줄임 규칙을 적용했다.
- 기록 보관함·알림·마이의 제목, 일정 이름과 장소, 뉴스 기사 미리보기, 대화 안의 결과 링크도 목록별 높이를 유지하도록 정리했다. 본문 없는 메모도 요약 줄의 공간을 유지한다.
- 말줄임은 목록 미리보기에만 적용한다. 상세 제목·본문, 대화 메시지, 입력 안내와 선택 옵션 설명은 기존처럼 필요한 만큼 줄바꿈한다.
- 일정 카드 상세에서 정의되지 않은 `eventRow`를 참조하던 부분을 기존 일정 렌더러인 `scheduleEvent`로 연결했다.
- 긴 제목·여러 줄 설명·빈 본문·실행 결과 유무를 별도 미리보기 데이터로 확인했다. 320·390·768px에서 같은 목록 안의 행 높이가 일치하고 가로 넘침이 없었다. 모바일의 내 기능·대화 행은 80px, 태블릿의 대화 행은 기존 밀도인 86px를 유지한다.
- `npm run build`, `npm run check`, 기존 테스트 231개 통과.
