# 날짜·시간 입력 통일 (2026-10-28)

## 방향과 기존 화면 점검

- design-taste-frontend의 기존 디자인 유지, 간격·타이포·대비·입력 상태 기준을 적용했다. 마케팅 화면 전용 구성 규칙은 제품 폼에 적용하지 않았다.
- DESIGN_VARIANCE 4 / MOTION_INTENSITY 4 / VISUAL_DENSITY 4. 기존 화면 구조를 유지하고 선택창의 표시·닫기 전환에만 움직임을 사용한다.
- 모리의 녹색 accent, 밝은 canvas와 dark 토큰, 시스템/Pretendard 글꼴, 14px 입력 모서리를 유지한다.
- 기존에는 일정만 앱 선택창을 사용했고 주차·뉴스·내 기능에는 브라우저 시간 입력이 남아 있었다. 선택창은 440px 최대 폭으로 태블릿에서도 좁은 가운데 창으로 표시됐다.

## 변경

- 휴대폰·768px 태블릿에서는 하단 선택창이 화면 폭을 채운다. 넓은 화면은 최대 816px이며 내부 760px 영역이 편집 화면의 읽기 폭과 맞는다.
- 날짜·시간·기간이 취소/제목/완료 헤더와 동일한 여백·선택 표시를 공유한다. 태블릿도 하단에서 열리고 같은 방향으로 닫힌다.
- 시간 휠은 24시간과 분을 두 열로 나누며 한 줄 전체에 선택 상태를 표시한다. 불필요한 사용법 문장은 없앴다.
- 날짜는 여섯 주를 유지하여 달 이동 시 창 높이가 달라지지 않는다. 선택 날짜는 원형으로 표시하며 320px 화면에서도 날짜 터치 영역은 44×48px이다. 작은 높이에서는 내용만 스크롤하고 완료/취소는 고정한다.
- 작은 글자·완료 버튼·선택 날짜의 대비를 보강하고 키보드, 초점 복귀, 동작 줄이기 설정을 유지했다.

| 화면 | 공통 입력 |
| --- | --- |
| 일정 추가·편집 | 날짜, 시작 시간, 소요 시간 |
| 주차 위치·표시 설정 | 표시 시작 시간, 표시 기간 |
| 뉴스 설정 | 브리핑 시간 |
| 내 기능 생성·편집 | 실행 시간, 시간 지정 해제 |

- 선택 중인 값은 완료 때만 원래 입력에 반영한다. 취소·뒤로가기는 작성값을 유지한다.
- 내 기능의 빈 시간은 선택창을 열기만 해서는 변경되지 않는다. 완료 시 반복 설정과 함께 갱신되며, ‘시간 지정 안 함’을 누르면 ‘필요할 때’ 실행으로 돌아간다.
- 초안 복원, 예시 채우기, 반복 모드 변경 후 실제 값과 버튼 표시가 함께 갱신된다. 필수 안내도 도움말·오류 연결을 보존하면서 갱신한다.
- 필드명·순서·저장값 타입은 유지한다. 계정 주차 폼도 같은 렌더링을 사용하지만 현재 활성 진입점이 없어 서버 저장 흐름은 이번 검증에 포함하지 않았다.

## 확인

- `npm run build`, `npm run check`, 전체 테스트 343개 통과.
- ego-browser에서 320×568, 390×844, 768×1024, 1024×900 화면 확인. 밝은/어두운 테마, 날짜 선택, 시간·기간 변경, 취소·완료·시간 지우기, 뉴스 초안 재개와 브라우저 뒤로가기를 점검했다.
- 320px 날짜 입력의 가로 넘침 없음, 768px 선택창 전체 폭 확인. 테스트에 사용한 preview 저장값은 원래대로 복원했다.
- 실제 iOS Safari 기기의 터치 관성·스크린리더·가상 키보드는 미검증이다. 브라우저 에뮬레이션을 실제 기기 검증으로 간주하지 않는다.
