# 일정 폼 선택 UI · 2026-10-27

일정 추가·편집의 날짜와 시작 시간은 브라우저 기본 date/time 팝업을 열었고, 소요 시간은 폼 내부에서 선택 목록을 펼쳤다. 플랫폼별 모양이 달랐으며 소요 시간 목록을 열면 주변 입력과 아래 내용이 이동했다.

일정 폼의 세 필드를 앱 안의 선택창으로 바꿨다. 휴대폰 폭에서는 하단 시트, 넓은 화면에서는 작은 중앙 선택창으로 표시한다. 날짜는 달력·연월 선택·오늘/내일 단축 동작을 제공하고, 시간은 24시간 시/분 휠, 소요 시간은 기간 휠을 사용한다. 입력칸의 너비·높이·줄바꿈을 제한하고 실제 값을 담는 input은 화면 흐름에서 제외하여 주변 필드를 밀지 않는다.

선택 중에는 별도 임시 값만 변경한다. 완료를 눌렀을 때 원본 input에 반영하며 input/change 이벤트를 보내 미리보기·초안·오류 해제를 갱신한다. 취소·Escape·배경 탭·뒤로가기에서는 값을 변경하지 않는다. 필드의 원래 date/time 타입·required와 FormData 이름은 유지하며, 검증 오류는 보이는 선택 버튼에 연결한다. 기존 분 단위 시간과 표준 목록에 없는 저장된 소요 시간도 유지한다.

선택창을 기존 탐색 이력에 한 단계로 포함했다. 뒤로가기는 선택창을 닫고 기존 폼과 스크롤을 복원한다. 앞으로가기는 선택창을 복원한다. 저장·확정 전에 폼이 분리되면 늦은 결과를 쓰지 않는다. 기존 카드 확대·기능 필터·달력 접힘 정책은 변경하지 않았다.

검증: 전체 자동 검사 **338개** 통과. 유효/윤년 날짜, 자정·분 단위 시간, 기존 특수 소요 시간, 취소와 확정, 분리된 폼, 휠 위치/선택, 네이티브 제약과 오류 포커스, 선택창의 뒤로/앞으로 흐름을 검사했다. 빌드·구문·diff 검사도 통과했다.

범위는 일정 추가·편집 폼의 날짜·시작 시간·소요 시간이다. 다른 폼의 기본 시간 입력은 이번 변경 범위에 포함하지 않았다. 브라우저 접근 거부가 해제됐다는 새 확인이 없어 실제 기기 화면·터치 관성·시각적 배치 검증은 미완료다. 휠은 웹의 스크롤 스냅으로 구현했으며 OS 기본 선택창과 동일한 물리 효과를 보장하지 않는다.
