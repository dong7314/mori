# PoC 후속 UI/UX 구현과 검증

2026-10-20 검토에서 남긴 세 항목을 2026-10-21에 구현했다. 승인된 파스텔 색상·버튼 그림자·글라스 표현과 기존 기능·저장 데이터를 기준으로 작업했다. 태블릿 배치와 음성 입력의 브라우저 검증은 완료했다. 카드 그래픽은 사용자 피드백에 따라 기능 화면을 축소한 SVG로 바꾸고 브라우저에서 다시 확인했다. 실제 기기와 사용자 검토는 남아 있다.

## 2026-10-22 입력창 고정과 제품 문구 정리

음성 모드에서 안내 각주가 사라지고 입력줄의 패딩·여백이 바뀌면서, 입력창이 26px 아래로 이동했다. 각주를 제거하고 접힘·펼침·녹음·입력 완료에 동일한 하단 여백과 입력줄을 적용했다. 음성 구분선은 입력줄의 크기를 바꾸지 않는 장식으로 분리했다.

- 음성 영역만 입력줄 위에서 펼쳐지고 접힌다. 음성 헤더는 둥근 상단 경계를 따라 움직이며, 내용은 입력줄 앞에서 잘린다. 입력줄에는 이동·크기 보간·페이드를 적용하지 않는다.
- 이전 화면을 고정할 때 입력란과 두 버튼은 복제하지 않는다. 초안·커서·입력 노드는 그대로 유지하고, 이전 음성 영역만 전환에 사용한다. 빠른 재전환·닫기·화면 크기 변경·움직임 감소 시 관련 레이어와 애니메이션을 정리한다.
- 320px 기본 글자에서는 입력란과 버튼을 한 줄에 유지한다. 글자를 크게 해 폭이 부족하면 입력란은 위쪽 전체 너비를 쓰고 버튼은 그 아래 오른쪽에 배치한다. 이 규칙도 음성 모드에 따라 달라지지 않는다.
- ‘예시 응답’, ‘이 기기에 저장’, 정상 상태의 브라우저 구현 설명과 둘러보기의 체험 안내를 제거했다. 음성 도움말은 ‘이렇게 말해 보세요’로 정리했다. 새 대화 응답과 기능 상세의 체험 문구도 제품 문구로 바꿨다. 기존 저장 대화는 변경하지 않는다.
- 시간 변경·뉴스 상태 변경·타이머 완료 시각 이동은 기본 화면에서 숨긴다. 격리된 미리보기에 `tools=1`을 함께 지정한 경우에만 개발용 조작을 표시한다. 실제 데이터가 아닌 뉴스·시세의 샘플 표시, 음성 권한·오류·미지원 기능 안내는 유지한다.

### 확인 결과

390×844에서 같은 초안의 입력란·마이크·전송 버튼은 펼침 전·중간·후·접힘 후 모두 `top=777, bottom=821, height=44px`였다. 768×1024, 390×480에서도 각 화면의 하단 좌표가 음성 상태에 따라 바뀌지 않았다. 인식 완료로 초안이 길어지면 입력란은 위쪽으로만 늘어나며 버튼의 하단 위치는 유지한다. 글자 200%에서도 입력란이 한 글자 너비로 좁아지지 않도록 확인했다.

브라우저에서 녹음 대기·듣기·처리·완료, 긴 인식 내용, 권한 거절 후 직접 수정, 키보드 복귀, 빠른 연속 전환, 녹음 중 화면 크기 변경과 움직임 감소를 확인했다. 입력란 복제와 남은 전환 레이어가 없고 초안이 유지됐다. 음성 상태는 모의 인식 콜백으로 검증했다. 빌드·구문 검사와 전체 **212개** 테스트가 통과했다. 실제 iPhone/iPad의 소프트 키보드와 마이크 권한 창은 별도 검증 대상이다.

## 2026-10-22 실제 조작으로 확인한 목록·음성·채팅 복귀 보완

앞선 모션 정리에서 대기 상태의 음성 폼에도 고정 높이가 적용돼 예시 아래에 빈 공간이 남았다. 그룹 목록은 안쪽 행에만 호버 배경을 칠해 바깥 모서리와 어긋났고, 채팅 종료 직전에 음성 화면을 초기화해 복귀 전환이 시작되기도 전에 내용과 배치가 바뀌었다. 사용자 제보 화면을 `ego-browser`에서 직접 재현하고 수정했다.

- **목록:** 내용·구분선의 안쪽 정렬은 유지하고, 배경과 마우스 조작 영역은 그룹 가장자리까지 이어진다. 첫·마지막 행은 바깥 모서리에 맞춰 잘린다. 대시보드·기록·대화·기능·설정·안내·시간·종목·테마 목록에 같은 규칙을 적용했다.
- **음성 높이:** 고정 크기는 녹음 대기·듣기·처리 중에만 사용한다. 초기 대기·예시·오류·직접 입력·입력 완료는 내용에 맞는 크기를 사용하며 작은 화면에서는 하나의 내부 스크롤로 제한한다.
- **펼침과 접힘:** 예시와 음성 폼은 고정된 이전 화면과 다음 화면 사이를 clip·opacity로 연결한다. 열기 280ms·닫기 240ms이며, 폼 높이나 글자 크기를 매 프레임 바꾸지 않는다. 전환 복제본은 조작·폼 연결·스크롤 탐색에서 제외하고 종료·재전환·화면 크기 변경에 정리한다.
- **종료 후 위치:** 음성 모드에 따른 레이아웃은 실제 입력 폼만 참조한다. 전환 복제본이 음성 모드를 유지시키며 종료 직후 입력창을 다시 움직이던 문제를 없앴다.
- **채팅 복귀:** 모바일은 아래에서 열리고 화면 아래로 돌아간다(420/320ms). 태블릿은 28px 이동·작은 크기 변화와 투명도로 패널을 전환한다(300/220ms). 배경 딤도 같은 시간에 사라진다. 마이크와 콜백은 즉시 중단하되 화면은 종료가 끝날 때까지 유지한다.
- **보호 처리:** 종료 중에는 대화의 비동기 결과로 화면을 다시 그리거나 알림 상세를 열지 않는다. 이전 native close 이벤트가 재열린 채팅을 초기화하지 않으며, 초안·원래 조작 버튼의 포커스를 보존한다.

## 2026-10-22 음성 입력 안정화와 공통 모션 정리

`ego-browser`로 음성 입력과 각 탭의 실제 조작 흐름을 점검했다. 녹음 영역을 펼칠 때 폼의 높이를 460ms 동안 계속 바꾸면서 대화 영역도 매 프레임 줄어들고 있었다. 녹음 내용에는 별도 스크롤까지 있어 스크롤 표시가 나타나고 화면이 밀렸다.

음성 폼은 화면에 맞는 최종 크기를 먼저 적용하고, 나타나는 효과는 내부 요소의 투명도와 위치만 사용한다. 기본 높이는 최대 36rem·화면 높이의 72%이며, 헤더·입력창·큰 글자를 포함해 실제 공간이 부족하면 폼 안에서 줄어든다. 녹음 대기·듣기·처리 중에는 같은 크기를 유지한다. 음성 그래픽의 회전 영역도 제한해 장식이 스크롤 크기에 영향을 주지 않게 했다.

- 인식 내용은 별도의 스크롤 상자 대신 음성 영역 한 곳에서 읽는다. 긴 내용이나 작은 화면에서는 이 영역만 스크롤한다.
- 상태 변경은 제목과 안내 문구만 전환한다. 그래픽과 읽던 내용은 깜빡이지 않는다. 인식 완료 후 입력창의 흐림·직사각형 배경 효과는 없앴다.
- 음성 입력 중 빈 대화의 중복 소개와 하단 각주는 숨기고, 브라우저 음성 인식 안내는 음성 영역 안에 유지한다. 기존 대화가 있으면 대화 영역을 유지한다.
- 음성 작업 버튼은 글자 크기와 가용 너비에 따라 두 열 또는 한 열로 배치한다. 큰 글자에서도 버튼 문구가 한 글자씩 길게 늘어지지 않는다.

| 조작 | 공통 기준 |
| --- | --- |
| 버튼·목록·아이콘 | 눌림 140ms·해제 220ms의 색·투명도 반응. 위치를 들거나 전체 배경을 어둡게 하지 않음. 호버는 마우스 환경에만 적용 |
| 입력·요일·테마 선택 | 테두리·색·포커스 반응을 같은 시간과 곡선으로 통일 |
| 하단 탭 | 표시선의 최종 크기를 먼저 적용하고 430ms 동안 transform만 이동. 너비·높이의 매 프레임 변경 제거 |
| 시간 범위·폼 선택창 | 열기 160ms·닫기 120ms. 열자마자 키보드 포커스 가능, 닫는 동안 조작 차단 후 숨김. 빠른 재열기에도 이전 종료 이벤트가 새 창을 닫지 않음 |
| 대화·기록 검색 | 결과만 160ms 전환. 입력 노드·커서 유지, 한글 조합 중에는 전환 생략 |
| 음성 입력 | 펼침 260ms·상태 문구 160ms·확정된 입력 내용 220ms. 폼 높이를 보간하지 않음 |

탭 이동 시 목적지의 스크롤 위치를 진입 효과보다 먼저 복원하도록 수정했다. 시간 메뉴가 선택 항목에 포커스를 주면서 자기 진입 애니메이션을 취소하던 문제도 해결했다. 기존 카드 확장·복귀와 내부 페이지 이동은 유지한다.

### 검증

- 빌드·구문 검사와 전체 **192개** 테스트 통과. 메뉴 재열기·취소·포커스·모션 감소, 탭 표시선의 transform 전환, 검색 결과와 음성 초안 보존을 포함한다.
- 390×844에서 녹음 대기 → 듣기 → 처리 중 폼 높이가 일정함을 확인했다. 수정 전에는 녹음 중 약 23px 변화가 관측됐다. 최종 기본 화면에서는 불필요한 음성 스크롤이나 전체 화면 넘침이 없었다.
- 320·390·768px와 390×480px, 320px 글자 200%에서 가로 넘침과 대화 창 바깥으로 밀리는 현상이 없었다. 긴 인식 내용은 음성 영역 안에서 스크롤하며 녹음 종료 버튼에 도달할 수 있었다.
- 실제 버튼 호버 전후의 크기·위치가 같고 해당 버튼 배경만 바뀜을 확인했다. 터치 포인터에서는 호버 배경이 적용되지 않았다.
- 일정 선택창의 Escape 닫기·초안·포커스, 대화 검색 입력 유지, 기능 필터, 테마 적용, 카드 상세 → 원래 카드 포커스 복귀를 확인했다. 카드 종료 뒤 잔여 전환 레이어가 없었다.
- 모션 감소 설정에서 음성 그래픽과 주요 전환을 생략하며 조작은 유지한다. 음성 콜백은 격리된 검수 페이지에서 모의 구현으로 재현했다. 실제 마이크·음성 서비스·iPhone/iPad Safari·소프트 키보드 검증은 별도다.

## 2026-10-22 작업 시트에서 앱 탐색 페이지로 전환

설정·기록·편집까지 모두 떠 있는 창으로 표시하던 방식을 바꿨다. 아래의 공통 시트 규격은 짧은 선택에만 적용하고, 오래 읽거나 작성하는 화면은 가장자리까지 채우는 탐색 페이지로 표시한다. 모바일·태블릿 모두 바깥 여백·딤·흐림·그림자·모서리 없이 앱 화면으로 이어진다. 태블릿 본문은 최대 760px 읽기 폭을 유지한다.

- 안내·보관함·파일 가져오기·계정·요금제·테마·각 기능 상세·편집은 오른쪽에서 들어오고 뒤로가기로 돌아온다. 페이지의 세로 드래그 닫기는 사용하지 않는다.

- 카드의 공유 요소 확장은 유지한다. 카드에서 편집으로 이동하면 공통 페이지가 되고, 뒤로가기는 확장된 상세를 거쳐 원래 카드로 복귀한다. 팝업 포커스 관리를 위해 내부 HTML dialog 기반은 유지하며 별도의 URL 라우팅·브라우저 뒤로가기 이력을 추가한 것은 아니다.

## 2026-10-22 다이얼로그 표시 정책과 작업 흐름 통합

앞선 헤더·안내 화면 정리만으로는 같은 폼이 진입 경로에 따라 다른 모양으로 열리는 문제가 남았다. `ref`, 대시보드 카드에서 시작했는지, 이전 화면의 클래스에 따라 크기를 정하던 방식을 화면 역할에 따른 `sheetLayout()` 정책으로 교체했다. 아래의 이전 정리보다 이번 기준을 우선한다.

[Apple Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets)와 [Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts)의 역할·닫기·뒤로가기 지침, [ChatGPT 공식 iOS 설정 예시](https://help.openai.com/en/articles/11958281-updating-your-visual-experience-on-chatgpt)를 브라우저에서 확인했다. 공개 문서와 이미지 참고이며 실제 iPhone 앱을 설치해 조작한 것은 아니다.

| 역할 | 공통 처리 |
| --- | --- |
| 시간·테마·종목·날짜 선택, 로그인·대화 이름 설정 | 간결한 시트 규격. 긴 흐름 내부의 선택 단계는 부모 프레임 유지 |

모든 작업 시트는 중앙 제목, 왼쪽 뒤로가기, 오른쪽 닫기, 44px 조작 영역과 같은 본문 여백을 사용한다. 입력·선택 행과 테마·주차·계정·요금제 목록도 하나의 본문 스타일로 정리했다. 중복 소개 제목과 의미 없는 안내 문장을 줄였다.

저장·적용 버튼은 공통 하단 영역으로 옮겼다. 복제 버튼이 아니라 실제 제출 버튼을 `form` 속성으로 연결하므로 브라우저의 필수 입력 검증·Enter 제출·비활성 상태가 유지된다. 이전처럼 긴 폼마다 저장 위치가 다르지 않다. 본문만 스크롤하며 초안·선택창·오류 표시를 보존한다.

모바일 시트는 아래에서 열리고 태블릿은 중앙에 나타난다. 내부 이동은 이전 본문을 스타일·입력값·스크롤이 고정된 비활성 복제본으로 유지하며 새 화면이 앞에 들어오는 320ms 전환을 사용한다. 뒤로 이동은 반대로 진행한다. 복제본의 실제 폼 연결·이벤트 훅은 제거하고 전환 종료·취소·닫기에 정리한다. 요금제 → 로그인에도 뒤로 경로를 추가했다.

## 2026-10-22 카드와 상세 화면 전환의 연속성 보완

‘지금 챙길 것’과 ‘미리 보는 하루’의 카드가 같은 확장 경로를 사용한다. 예측 카드도 누른 항목의 제목·시간·설명·SVG를 상세 상단에 유지하고, 원래 예약 항목의 식별자와 발생 시각으로 복귀 대상을 찾는다. 주가 예측에는 금액이 없으므로 상세 본문에는 시세·등락을 별도로 유지한다. 일정의 중복 제목만 정리하고 날짜·장소·편집 기능은 보존한다.

기존에는 상세 너비로 배치한 글자의 크기를 전환 중 계속 바꿔 줄바꿈이 달라질 수 있었다. 이제 누르기 전 카드의 계산된 스타일과 줄바꿈을 비활성 DOM 복제본에 고정한다. 글자를 늘이거나 매 프레임 재배치하지 않고, 원본과 상세의 같은 요소를 같은 경로로 이동시키며 전환 도중 교차해서 보여준다. 그림은 비율을 유지한다. 상세 본문은 함께 나타나고, 전환 종료 시점에는 이미 최종 레이아웃이므로 마지막에 내용을 갈아 끼우지 않는다. 종료된 복제본은 제거하며 클릭·포커스·카운트다운 갱신에 참여하지 않는다.

뉴스·예약 실행으로 상세 내용을 다시 그려야 할 때는 진입 중 DOM을 교체하지 않고 최신 갱신만 대기시킨다. 닫는 중 도착한 갱신은 상세를 다시 열지 않는다. 빠르게 닫기·드래그 취소는 현재 위치에서 이어서 처리하고, 헤더를 가볍게 누르기만 했을 때 복제 레이어를 만들지 않는다. 가로 목록의 잘린 카드도 실제 스크롤 영역의 경계 안에서 시작한다. 움직임 줄이기에서는 복제본과 확장 애니메이션을 생략한다.

## 2026-10-22 대시보드 탐색과 각 화면의 작성 역할 정리

인사 아래의 주차 기억·일정 추가·메모 쓰기·대화하기 바로가기 줄을 제거했다. 인사 다음에 시간 기반 카드가 나오며, 태블릿에서도 인사 영역이 전체 열을 사용한다.

대시보드의 오늘 약속·최근 대화·기록은 확인과 탐색에 집중한다. 세 목록 하단의 추가 행을 제거하고, 제목 오른쪽에 이동 목적에 맞는 문구를 명시한다. 오늘의 약속은 **일정으로 >**, 최근 대화는 **대화로 >**로 탭 이동을 안내하고, 기록과 정리는 **전체 보기 >**로 보관함을 연다. 제목은 정보 이름, 오른쪽 버튼은 이동 동작으로 구분하며 크기와 여백은 통일한다.

| 영역 | 버튼과 목적지 | 목적지의 직접 작성 기능 |
| --- | --- | --- |
| 오늘의 약속 | 일정으로 → 일정 탭 | 일정 추가 → 대화 없이 작성 |
| 최근 대화 | 대화로 → 대화 탭 | 새 대화 → 대화 입력 |
| 기록과 정리 | 전체 보기 → 기록 보관함 | 새 메모·파일 가져오기 |

세 영역은 공통 `dashboardCollection()`으로 구성한다. 빈 목록도 같은 목적지 버튼을 유지하며, 대시보드 하단의 채팅·마이크로 요청하는 흐름은 유지한다. 보관함에서 메모·파일 화면을 연 뒤 뒤로 이동하면 보관함으로, 보관함을 닫으면 누른 전체 보기 버튼으로 복귀한다. 사용하지 않는 기록 추가 선택 화면과 생성 행 전용 스타일도 제거했다.

### 적용 판단

처음에는 ‘전체 보기 + 원형 +’를 같은 헤더에 배치했고, 이후 목록 하단에 중앙 정렬된 생성 행을 배치했다. 사용자 피드백에 따라 최종적으로 대시보드의 생성 행을 없앴다. 동일한 모양의 추가 버튼이 일정 작성·대화·기록 종류 선택으로 각각 다르게 열리는 혼란을 줄이고, 작성은 각 목적지에서 시작하도록 정리했다.

이전 단계에서는 [Apple 미리알림](https://support.apple.com/en-us/102484), [Apple 메모](https://support.apple.com/en-us/118442), [Todoist Dynamic Add](https://www.todoist.com/help/todoist/features/use-the-dynamic-add-button-in-todoist-ysybl2M1)의 공식 안내와 공개 스크린샷을 비교했다. 실제 앱을 설치해 조작한 것은 아니며, 이번 배치는 사용자 피드백과 모리의 기존 하단 입력부를 함께 고려한 설계 판단이다.

빌드·구문 검사와 전체 **149개** 테스트가 통과했다. 브라우저에서 일정·대화 탭 이동과 기록 보관함 진입, 일정 직접 작성, 새 대화, 보관함의 메모·파일 화면 진입과 복귀를 확인했다. 320·390·768px와 320px 글자 200% 확대에서 가로 넘침이나 제목·버튼 겹침이 없고, 이동 버튼은 기본 높이 44px를 유지한다. 화면: [모바일](screenshots/collection-actions/mobile.png), [태블릿](screenshots/collection-actions/tablet.png). 실제 iPhone·iPad Safari 검증은 별도다.

## 2. ‘지금 챙길 것’ 카드의 시각 요소

기본 기능 여섯 개의 오른쪽 그래픽은 큰 앱 아이콘 대신 각 기능의 내용을 보여주는 작은 화면으로 구성한다. 주차에는 주차장 구획, 뉴스에는 뉴스 지면을 표현하며 나머지 기능도 차트·메모지·달력·타이머로 구분한다. 180×144 좌표계의 inline SVG와 CSS를 사용하고, 현재 저장된 상태를 전달한다. 실사 이미지나 입체 렌더링은 사용하지 않는다.

| 기본 기능 | SVG 구성 | 연결하는 상태와 빈 화면 |
| --- | --- | --- |
| 주차 | 번호 없는 주차 구획과 통로, 저장 위치를 가리키는 핀 | 저장된 층과 자리 번호. 실제 주차장 도면·출입구·이동 경로를 제공하는 지도는 아니다. |
| 뉴스 | 주제와 기사 영역을 나눈 뉴스 지면 | 현재 주제, 수집 중·실패·완료 상태, 완료 시 실제 표시 중인 기사 수. 기사 자체는 기존 PoC의 예시 데이터다. |
| 관심 주가 | 관심 종목과 빨간색·파란색 캔들 차트 | 현재 선택한 종목과 예시 시세 표시. 봉의 몸통과 꼬리로 상승·하락을 구분하며 실제 가격 이력은 아니다. |
| 메모 | 제목과 본문 줄을 표현한 메모지 | 최근 메모의 실제 제목과 저장 개수. 본문은 줄 형태로 표현하며 저장 기록이 없으면 빈 상태로 구분한다. |
| 일정 | 날짜를 보여주는 달력과 일정 줄 | 실제 일정의 월·일·시각. 일정이 없으면 임의의 약속 대신 빈 격자를 보여준다. |
| 알림 | 남은 시간과 목표 시각을 구분한 타이머 | 현재 알림의 남은 시간·목표 시각. 활성 알림이 없으면 알림 없음으로 구분한다. |

대시보드의 현재 카드, 3시간·5시간·하루의 시간대별 카드, 기능 탭은 공통 `featureArt()`를 사용하며 해당 기능의 상태를 함께 전달한다. 기능 탭은 설명과 현재 상태를 왼쪽에, SVG 미리보기를 오른쪽에 둔다. 모바일은 한 열, 태블릿은 두 열을 사용한다. 클릭하면 기존 상세·메모 보관함·스케줄 화면으로 이동한다. 현재 대시보드에는 시간 없는 메모도 기본 기능 카드로 표시한다. 3시간·5시간·하루의 예약 보기에는 메모의 임의 실행 시간을 만들지 않는다. 사용자 기능은 기존 선택 아이콘을 유지한다.

SVG는 보조 표현이며 정확한 정보와 전체 문장은 카드 본문과 상세에 남긴다. 중복 낭독하지 않도록 장식 영역을 `aria-hidden` 처리하고, 사용자 입력은 이스케이프한다. 긴 제목과 자리 번호는 SVG 안에서만 줄여 표시한다. 주차 본문의 층과 자리는 구분점이 다음 줄에 남지 않도록 묶어 줄바꿈한다.

PNG·WebP와 외부 이미지 요청 없이 구성하며 새 라이브러리를 추가하지 않는다. 반복해서 렌더링되는 SVG 사이에서 고정 ID가 충돌하지 않도록 구성한다. 전역 심벌 아이콘·라우트·저장 구조는 유지한다. 글자를 확대해도 장식의 폭이 함께 커지지 않아 텍스트 공간을 보존한다. 새로운 호버 이동·무한 반복 모션은 추가하지 않고 기존 카드 전환을 유지한다.

구현: `src/card-visuals.mjs`, `styles/_card-visuals.scss`, `src/app-experience.js`.

## 3. 채팅 내부 음성 입력

별도의 음성 dialog를 제거했다. 모든 마이크 진입점은 현재 대화를 열고, 같은 입력창 안에서 음성 영역을 펼친다. 일정 하단의 음성 버튼도 정해진 예시 약속을 자동 실행하지 않고 이 흐름으로 들어온다.

1. 마이크 진입 시 현재 대화·작성 중인 문장을 유지한다. 이 시점에는 마이크 권한을 요청하지 않는다.
2. ‘녹음 시작’을 누르면 브라우저 음성 인식을 시작한다. 연결 대기·듣는 중·인식 중을 같은 영역의 상태 문구와 파형으로 구분한다. 파형은 입력 상태를 나타내는 모션이며 실제 오디오 진폭 측정값은 아니다.
3. 녹음 중에는 기존 초안을 유지하고 임시 인식 결과를 별도로 보여준다. 입력·전송을 잠가 결과가 다른 입력을 덮어쓰지 않게 한다.
4. 녹음이 끝나면 인식한 문장을 기존 초안 뒤에 한 번만 추가한다. 입력 완료 피드백과 짧은 전환 후 사용자가 문장을 수정하고 직접 전송한다. 완료된 문장은 음성 미리보기에서 반복 표시하지 않는다.
5. ‘키보드’는 인식 결과와 직접 수정한 내용을 유지하며 입력창으로 돌아간다. 음성 취소는 진행 중 결과를 버리고 기존 초안을 보존한다. 첫 Escape는 음성 영역만 접는다.
6. 미지원·권한 거부·마이크 없음·연결 실패·빈 녹음은 같은 대화 안에서 다시 시도하거나 텍스트·예시 입력으로 이어간다.

4,000자를 넘으면 원래 초안과 인식한 문장을 보존한 채 수정하도록 안내한다. 요청 취소와 대화 종료 후 도착한 콜백은 반영하지 않는다. 입력 완료 버튼을 반복해서 눌러도 같은 문장을 중복 추가하지 않는다. 인식 종료 이벤트가 오지 않는 경우에도 대기 시간을 제한하고 오류 복구 경로를 제공한다.

구현: `src/voice-session.mjs`, `styles/_inline-voice.scss`, `index.html`, `src/app-experience.js`.

## 2026-10-21 기본 기능 노출과 주가 표현 보완

‘지금 챙길 것’에서 주차·뉴스·주가·메모·일정·알림을 모두 확인할 수 있도록 표시 범위를 넓혔다. 현재 시간에 해당하는 주차·예약·일정·알림·사용자 기능을 기존 순서대로 먼저 두고, 아직 없는 기본 기능 카드를 이어 붙인다. 하나의 기본 기능을 같은 카드로 반복하지 않으며, 현재 표시 시간에 해당하는 서로 다른 알림은 각각 유지한다. 이런 알림이 이미 있으면 일반 알림 카드를 추가하지 않는다.

주차·메모·일정·알림 기록이 비어 있어도 기능에 접근할 수 있는 카드를 남긴다. 이때 저장 위치·약속·메모·알림을 임의로 생성하거나 등록된 것처럼 표시하지 않는다. 현재 정보의 우선순위를 계산하는 `visibleCards()`와 대시보드에 필요한 기본 기능을 보충하는 `dashboardCards()`를 구분한다. 3시간·5시간·하루 보기는 기존 시간 계산을 유지한다.

주가의 오른쪽 SVG와 상세 차트를 선형 그래프에서 캔들 차트로 바꾼다. 상승은 빨간 봉, 하락은 파란 봉으로 표시하고 각 봉의 몸통과 꼬리를 그린다. 관심 종목·기간 변경 흐름은 유지하며, 표시한 봉과 시세는 PoC의 예시 데이터다. 실시간 시세나 실제 과거 이력을 연결한 것으로 안내하지 않는다.

## 2026-10-21 카드에서 상세 페이지로 확장

‘지금 챙길 것’의 여섯 기능 카드는 누른 위치와 크기에서 전체 화면으로 펼쳐진다. 카드의 배경·제목·요약·SVG를 상세 상단에 이어 붙이고 본문은 뒤이어 표시한다. 확대할 때 글자 전체를 늘리지 않고 위치와 글자 크기를 각각 조정한다. 닫으면 원래 카드로 접히며 대시보드의 스크롤 위치와 키보드 포커스를 유지한다.

빌드·구문 검사와 전체 **136개** 테스트가 통과했다. 브라우저에서 여섯 카드의 열기·닫기, 상세를 스크롤한 뒤 복귀, 주차·메모 편집 후 뒤로 이동, 일정 추가 화면과 달력 이동, 첫 알림 생성 후 복귀를 확인했다. 320·390·768px에서 상세가 화면 전체를 채우고 가로 넘침이 없었으며, 밝은·어두운 테마와 움직임 줄이기를 확인했다. 검사용 알림과 미리보기 설정은 검수 전 값으로 복구했다. iPhone·iPad 실기기 Safari 검증은 남아 있다.
