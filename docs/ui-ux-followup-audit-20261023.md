# UI/UX 후속 점검

2026-10-23 · `poc` · 기준 커밋 `0d9874a`

## 점검 범위와 한계

현재 진입점인 `index.html`과 `src/app-experience.js`, 화면 전환·폼 오류·초안·문서 저장 모듈 및 관련 SCSS를 검토했다. 앱 코드는 수정하지 않았다.

로컬 미리보기의 브라우저 접근이 승인 단계에서 거절되어 이번에는 실제 화면을 조작하거나 픽셀 단위로 측정하지 못했다. 아래 결과는 코드에서 확인한 동작과 누락 사항이다. 기존 `mobile-ui-audit-20261023.md`의 화면 검증 결과는 과거 자료로만 참고했다.

## 발견 사항

### 1. P1 — 저장 실패가 성공 안내로 덮이는 화면이 있다

- 위치: `src/app-experience.js:98`, `:1078`, `:1102`, `:1021`.
- 메모·일정·내 기능 저장은 `save()`의 반환값을 확인하고 실패 시 데이터를 되돌린다.
- 반면 주차 위치와 브리핑 설정 저장은 반환값을 무시하고 상세 화면으로 이동한 뒤 성공 토스트를 표시한다. 일정 삭제·복원 등에도 같은 패턴이 있다.
- 재현 조건: 저장 공간 부족 또는 브라우저 저장소 쓰기 실패 상태에서 해당 변경을 저장한다.
- 영향: 사용자에게 저장됐다고 안내한 값이 새로고침 후 사라지거나, 삭제했다고 안내한 일정이 다시 나타날 수 있다. `save()`의 실패 토스트도 뒤이은 성공 토스트에 덮인다.
- 개선: 변경 전 상태 보관 → 저장 성공 확인 → 화면 이동·성공 안내 순서를 모든 쓰기 동작에 적용한다. 실패 시 현재 폼을 유지한다.
- 확인: 실제 주차·브리핑 submit 분기 코드를 추출해 `save() => false`로 실행했다. 두 분기 모두 메모리 상태를 변경하고 성공 메시지를 호출했다. 브라우저를 통한 재현은 하지 않았다.

### 2. P2 — 공통 폼 오류 처리가 실제 입력 흐름 전체에 적용되지 않는다

- 위치: `src/app-experience.js:587`, `:1043`, `:1049`, `:1074`, `:1078`; `src/form-feedback.mjs:12`.
- 빈 메모는 앱의 오류 메시지·포커스·ARIA 연결을 사용한다. 일정 이름·브리핑 주제·프로필 이름 등은 `required`에 의한 브라우저 기본 검증이 submit 이벤트보다 먼저 실행된다. 이를 공통 오류로 연결하는 `invalid` 처리도 없다.
- 주차 위치를 모두 비우거나 예약 표시의 요일을 모두 해제하는 업무 검증 오류는 `showFormError(form, message)`에 필드 정보 없이 전달된다. 네이티브 검증상 유효한 경우 해당 입력 대신 폼 상단 요약으로 이동한다.
- 영향: 같은 저장 버튼을 눌러도 오류 모양·표현·위치가 브라우저와 폼마다 달라진다. 요일 오류에서 어느 항목을 수정해야 하는지 직접 연결되지 않는다.
- 개선: 네이티브 검증 오류도 공통 표시 방식에 연결하고, 주차 업무 검증은 대상 필드·필드셋을 명시한다. 요일 그룹의 오류 해제 동작까지 연결한다.

### 3. P2 — 전체 화면 상세·대화와 브라우저 뒤로가기가 연결되지 않는다

- 위치: `src/app-experience.js:393`, `:449`, `:539`, `:1247`.
- 하단 탭은 hash로 이동하지만, 상세·폼은 메모리의 `sheetTrail`, 대화는 dialog 열림 상태로 관리한다. 상세를 열 때 브라우저 방문 기록에 단계를 추가하지 않는다.
- 확인 경로: 홈 → 기능 탭 → 기능 상세 → 브라우저 뒤로가기.
- 영향: 앱의 뒤로가기 버튼은 상세를 닫지만 브라우저 뒤로가기는 이전 탭으로 이동한다. `route()`는 열린 상세를 닫지 않으므로 뒤의 탭만 바뀔 수 있다. 진입 기록에 따라 앱 페이지를 벗어날 수도 있다.
- 개선: 상세·대화 진입과 내부 복귀 단계를 브라우저 방문 기록과 동기화한다. 기기 뒤로가기·브라우저 뒤로가기·헤더 뒤로가기가 같은 단계를 처리하게 한다.
- 한계: 실제 Android 뒤로가기 제스처와 iPhone Safari 동작은 별도 확인이 필요하다.

### 4. P2 — 파일을 보관할 수 있지만 정리하는 흐름이 없다

- 위치: `src/app-experience.js:98`, `:899`, `:902`; `src/document-store.mjs`.
- 파일 가져오기와 원문 다운로드는 있지만 보관 문서 삭제 동작은 없다. 원문 저장 모듈에도 삭제 함수가 없다.
- 저장 실패 안내는 “문서나 오래된 기록을 정리해 주세요”라고 안내한다.
- 영향: 잘못 가져왔거나 중복된 문서가 계속 남고, 용량 문제를 앱 안에서 해결하기 어렵다. 안내가 제시하는 해결 방법을 실제 UI로 수행할 수 없다.
- 개선: 문서 상세에 삭제·복구 흐름을 추가하고 메타데이터와 원문을 함께 정리한다. 대화·내 기능도 생성 이후 정리 기능의 범위를 함께 검토할 필요가 있다.

### 5. P2 — 입력 중 뒤로 갔다가 돌아왔을 때의 복구 규칙이 다르다

- 위치: `src/app-experience.js:68`, `:552`, `:666`; `src/form-drafts.mjs:7`.
- 메모·일정·내 기능 폼만 초안 캡처 대상으로 등록되어 있다. 주차·브리핑 설정은 수정 중 닫으면 다시 열 때 마지막 저장값으로 돌아간다.
- 폼 초안은 메모리 Map에만 있어 새로고침하면 사라진다. 대화 초안은 앱 저장 데이터에 포함되어 새로고침 후에도 복구될 수 있다.
- 영향: 같은 앱에서 사용자는 어떤 입력이 복구되는지 예측하기 어렵다. 특히 주차의 표시 시간·요일을 조정하다 뒤로 가면 다시 입력해야 한다.
- 개선: 폼별 복구 정책을 정하고, 저장 전 입력이 있는 폼의 뒤로가기 동작을 통일한다. 지속 보관하는 초안과 현재 세션에서만 복구하는 초안을 UI에서 명확하게 안내한다.

### 6. P2 — 기록 필터 변경 시 포커스가 선택한 필터에서 제목으로 이동한다

- 위치: `src/app-experience.js:132`, `:490`, `:537`, `:971`.
- 기록 종류 필터는 `recordsSheet()`로 시트 본문 전체를 교체한다. 기존 버튼이 제거된 뒤 `openSheet()`가 시트 제목에 포커스를 준다.
- 비교: 기능 탭의 필터와 일정의 보기 방식 변경은 렌더 후 같은 컨트롤로 포커스를 복원한다.
- 영향: 키보드·스크린리더 사용자는 필터를 바꿀 때마다 컨트롤 위치를 다시 찾아야 한다. 검색 입력은 유지하도록 개선했지만 종류 필터에는 같은 원칙이 적용되지 않았다.
- 개선: 검색·필터 컨트롤을 유지하면서 결과 목록과 건수만 갱신한다. 전체 렌더가 필요하면 선택 필터로 포커스를 복원한다.

## 권장 순서

1. 저장 실패와 성공 안내의 충돌을 먼저 수정한다.
2. 공통 오류 처리와 초안 복구 정책을 정리한다.

- 320·390·768px에서 긴 제목, 상태 태그, 날짜가 함께 있을 때 목록의 정보 식별성.

- 상세·편집·보관함을 오가는 복귀 포커스와 스크롤 위치.

이번 점검을 위한 별도 UI 테스트는 실행하지 않았다. 이전 pull 직후 통과한 231개 테스트는 회귀 참고 자료이며, 위 UX 흐름 전체를 검증하는 근거로 보지는 않는다.

## 필터 탭 전환 개선 · 2026-10-24

- 일정의 월·주·일과 기능의 모든 기능·기본 기능·내 기능을 바꿀 때 전체 본문을 재생성하던 흐름을 콘텐츠 영역 갱신으로 변경했다. 헤더와 실제 탭 버튼은 유지한다.
- 선택 배경은 300ms 동안 이동한다. 콘텐츠는 선택 방향에 따라 10px 슬라이드와 짧은 페이드로 전환하고, 이전 콘텐츠는 180ms 동안 사라진다. 카드별 투명도 0 진입 애니메이션은 필터 전환에서 재생하지 않는다.
- 콘텐츠 영역의 높이도 300ms 동안 보간하여 월/주/일 또는 목록 길이 차이가 한 프레임에 바뀌지 않도록 했다. 빠른 연속 선택은 현재 높이에서 이어가며, 이전 애니메이션의 지연된 종료가 마지막 선택을 정리하지 못하게 했다.
- 이전 화면의 시각 복사본은 `inert`·`aria-hidden`으로 처리하고 ID·동작 속성을 제거한다. 동작 줄이기, 화면 이동, 애니메이션 미지원 시에는 복사본과 고정 높이를 정리한다.
- 빌드·문법 검사·테스트 258개 통과. 이번 신규 7개는 빠른 반대 방향 전환·복사본 정리·높이·동작 줄이기·실제 두 필터 핸들러의 컨트롤 유지를 검증했다.
- 실제 화면 자동 검증은 저장된 브라우저 권한의 `localhost:4173` 접근 차단으로 진행하지 못했다. 시각적 품질을 브라우저에서 확인했다고 간주하지 않는다.

## 원본 느낌 복구 · 2026-10-24

사용자가 “원본 느낌 유지하고 속도·끊김만 개선”을 선택했다. 기준은 오늘 pull한 `0d9874a`의 즉시 화면 갱신과 은은한 단일 진입이다. 가로 슬라이드·화면 복제·전체 높이 보간뿐 아니라, 이후 추가했던 완전한 페이드아웃과 지연 갱신도 폐기했다.

## 현재 전환 정책 · 2026-10-24 캘린더 연결 전환

- 일정: 월·주·일 모두 같은 월 전체 날짜 DOM을 유지한다. 별도의 격자 표시 영역 높이와 격자 전체의 세로 위치만 같은 420ms 이징으로 전환하여 선택 주를 연속해서 접거나 펼친다. 날짜 셀의 밝기·크기·행 간격은 고정한다. 날짜별 순차 진입·겹치는 날짜 레이어·화면 복제는 없다. 빠른 역전환은 CSS 전환의 현재 값에서 이어진다.
