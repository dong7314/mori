# Mori 채팅 API

현재 계약은 **0.9.0**이며 [전체 기능·배포 문서](poc-backend-0.9.md)의 채팅 절을 따른다. 화면은 작업을 등록하고 진행 이벤트를 관찰한다. API 연결 수명과 실제 실행 수명은 분리되어 있다.

## 요청 흐름

| API | 역할 |
|---|---|
| `POST /v1/conversations` | 대화 생성 |
| `GET /v1/conversations` | 본인 대화 목록·검색 |
| `POST /v1/conversations/{id}/runs` | 작업 등록, 202와 상태/이벤트 주소 반환 |
| `GET /v1/conversations/{id}/runs/{run_id}/events` | 저장 이벤트 재생·진행 관찰 |
| `GET /v1/conversations/{id}/runs/{run_id}` | 최종 상태·결과 확인 |
| `POST /v1/conversations/{id}/runs/{run_id}/cancel` | 실행 취소 요청 |
| `GET /v1/conversations/{id}/messages` | 사용자 메시지·답변·결과 참조 |
| `POST /v1/conversations/{id}/messages` | 기존 클라이언트용 등록+SSE 관찰 |

인증에는 Mori access token을 사용한다. 실행 POST는 UUID `Idempotency-Key`가 필수다. 같은 사용자 요청의 재전송에는 같은 키를 유지한다. SSE ID는 `<run UUID>:<순번>`이며 `Last-Event-ID` 또는 `after`로 이어 읽는다. 중복 이벤트는 ID로 제거한다. SSE 관찰은 기본 25초 뒤 끝나며 재연결해야 한다. 관찰 종료가 작업 종료를 뜻하지 않는다.

대화 목록은 `last_message`와 `last_activity_at`을 반환한다. 마지막 요청의 답변이 없으면 사용자 메시지를 미리보기로 사용한다. 날짜 그룹과 정렬은 메시지 활동 시각을 사용하므로 제목 수정·상단 고정으로 과거 대화가 오늘로 이동하지 않는다. 빈 대화는 생성 시각을 사용한다. `updated_at`은 대화 관리 작업의 변경 시각으로 남는다.

브라우저에서는 인증 헤더가 필요한 fetch 스트림을 사용한다. 네트워크 청크 경계와 SSE 프레임 경계가 다르므로 빈 줄까지 모아서 파싱한다. 응답 텍스트를 HTML로 바로 삽입하지 않는다. 진행 이벤트는 도구 호출·저장 상태이며 숨겨진 추론은 반환하지 않는다.

## 저장과 권한

주차·메모·일정·알림·기능 생성 및 문서 작업을 지원한다. 일반 대화에서는 뉴스 주제·수집 시간과 주가 종목·예약을 설정하고, 실제 뉴스 수집·시세 조회 결과로 이동할 수 있다. 외부 조회 후에도 실행 상태·소유자·설정 버전을 확인한 뒤 결과와 완료 기록을 함께 저장한다. 조회 실패를 성공 답변으로 바꾸지 않는다.

사용자 기능을 선택하면 고정된 버전과 `allowed_actions`를 검사한다. 기능의 기본 권한은 `reply`다. 모델이 사용자 기능을 만들면서 스스로 저장 권한을 부여하지 못한다. 뉴스·주가 일반 대화 액션도 사용자 기능의 권한 우회 수단으로 사용할 수 없다. batch는 서로 다른 2~4개 저장 작업을 묶으며 저장과 완료 기록을 한 트랜잭션으로 처리한다. 뉴스·주가 설정은 묶을 수 있지만 외부 조회 액션은 batch에 포함하지 않는다.

일반 대화에서 사용자 기능을 찾을 때는 활성·중지·작성 중 상태를 함께 제공한다. `feature_lookup`은 모델에 실제 전달한 최대 50개 기능의 ID 범위 안에서 본인 소유·미삭제 상태를 다시 확인하고, 현재 상태와 `/v1/features/{id}` 참조만 반환한다. 중지된 기능을 자동 재개하거나 실행하지 않으며 기능 결과도 만들지 않는다. 목록이 잘렸으면 잘림 여부를 함께 알린다. 뉴스·주가 기본 기능은 각각 전용 설정 문맥을 사용한다.

채팅에서 기능을 만들라는 요청에 정확히 같은 제목의 사용자 기능이 있으면 기존 상세를 안내한다. 기존 내용·허용 작업·예약·상태를 바꾸지 않는다. 직접 입력 폼/API에서는 같은 제목을 따로 만들 수 있다. 사용자 기능의 ‘오늘 메모’ 문맥은 마지막 내용 저장 시각으로 고르며, 삭제 후 되돌리기만 한 메모는 저장 날짜가 바뀌지 않는다. 예약이 지연되어도 실행 기준 날짜는 원래 예약 시각과 시간대다.

수동·예약 뉴스 실행 모두 대화의 결과 참조로 `/v1/news`에 이동할 수 있다. 참조는 현재 브리핑 화면을 가리키며, 요약 실패로 이전 브리핑을 유지한 경우에는 완료 답변과 브리핑의 상태도 함께 확인한다.

주차 저장과 조회는 모두 `result_refs.kind=parking`과 `/v1/parking-records/latest`를 반환한다. 저장한 위치가 없는 조회에는 참조가 없다. 예약 주가 완료에는 `kind=stock`, `/v1/market/snapshot` 참조와 기존 `feature_result` 참조를 함께 남긴다. 주가 참조는 최신 설정의 스냅샷이고, 해당 회차 당시 가격·시각·제공자는 실행 결과에서 확인한다. 클라이언트는 액션 이름 대신 결과의 `kind`와 `detail_url`을 기준으로 상세 화면을 연결한다.

문서의 `action.queued`는 작업 접수다. `document_job`을 조회해 실제 파일 완성을 확인한다. 알림 목표 저장과 Web Push 전달도 각각 상태를 확인한다. 서버는 완료하지 않은 동작을 최종 성공 문구로 대신하지 않는다.

## 실행 환경

`MORI_CHAT_ENABLED=true`와 `MORI_CHAT_WORKER_ENABLED=true`, 실제 `mori worker`가 필요하다. 무료 공용 gateway는 서버가 인증 사용자 ID를 전달하고 사용자별 프로세스·홈·키를 분리한다. Pro 자동 배정은 별도 provisioner와 개인 Knative/PVC를 사용한다. 기존 `MORI_HERMES_TEST_USER_ID`는 단일 테스트 계정용으로 남아 있다.

DB lease로 중단된 worker 작업을 복구한다. 권한·런타임·기능 정의 변경은 저장 직전 다시 검사한다. 클라이언트 연결 종료는 작업을 취소하지 않는다. 명시적 취소도 이미 완료된 작업을 자동으로 되돌리지 않는다.

`backend/scripts/test_chat.py`는 기존 SSE 요청의 짧은 진단용이다. 긴 작업의 최종 결과는 run 상태 조회로 확인한다. UI 재접속 구현에는 위 `/runs`와 `/events` 계약을 사용한다.
