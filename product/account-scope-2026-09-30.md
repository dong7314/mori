# 마이 화면 범위와 계정 정책

최초 기준일: 2026-09-30 · 현황 갱신: 2026-11-03 · master `6285aba` / API 0.9.0 · [전체 계획](../plan.md)

마이는 로그인·로그아웃, 사용자 정보와 이름 수정, 테마, 무료·Pro 요금제 안내와 결제 관리만 다룬다. 기능의 수행 조건과 예약은 해당 기능 상세에서 관리한다. PoC와 실제 서비스의 현재 연결 상태는 구분한다.

| 항목 | 현재 서버 구현 | 제품 화면·실환경에서 남은 작업 |
| --- | --- | --- |
| 로그인·로그아웃 | 네이버·카카오 OAuth, 토큰 교환/갱신/로그아웃, 계정 세션 | 실제 제공자 왕복, 제품 웹 세션·WebView 교환 구현과 RN 인증 복귀 |
| 사용자 정보 | 이름·가입일·소셜 정보·서버가 판단한 유효 등급 | PoC 계정 프록시와 별도로 제품 React/RN 연결 |
| 이름 수정 | PATCH와 revision 충돌 검사 | 다른 기기 편집 충돌·저장 후 재조회 UI |
| 테마 | 계정의 시스템·라이트·다크 설정 | 제품 공통 테마와 RN 시스템 테마 연결 |
| 무료 | 결제 없이 사용, Free 실행은 공용 gateway의 사용자별 프로필 | 사용량/기능 한도 확정, 실제 다중 사용자 실행 검증 |
| Pro | 관리자 승인 또는 유효한 유료 기간, 개인 Knative 배정 코드 | 가격·정책 확정, 실제 결제·개인 환경 준비/회수 인수 |
| 웹 결제 | Toss checkout·빌링키·서버 가격 청구·주문 확인·갱신/확인 worker | 실제 테스트 상점·고정 콜백·결제 상태 UI·외부 제공자 검증 |
| 구독 해지·재개 | 기간 말 갱신 중단/재개, 제공자가 확인한 취소·환불 상태 반영 | 해지 예약과 이용 종료를 구분하는 화면, 실패/확인 대기/이미 종료된 구독 인수 |

현재 Pro가 ‘관리자 승인만 가능’하거나 결제/해지 API가 ‘준비 중뿐’이라는 이전 설명은 0.9 코드에는 해당하지 않는다. 다만 서버에 설정과 worker가 없으면 결제를 이용할 수 없으며, 실제 판매 가격은 서버 설정으로 정한다. PoC의 비활성 결제 버튼을 서버 결제 미구현의 근거로 쓰지 않는다. 실제 결제/상점 연결은 아직 검증하지 않았다.

무료 선택을 결제 거래로 만들지 않는다. 관리자 승인과 유료 기간은 독립 권한 근거다. 유료 결제가 취소돼도 별도 관리자 승인을 자동 회수하지 않는다. 화면에는 서버가 반환한 `access_source`, `billing_status`, `cancel_at_period_end`, `current_period_end`를 사용하고 로컬 가짜 Free/Pro 토글로 권한을 바꾸지 않는다.

기간 말 해지는 즉시 환불이 아니다. 이미 종료된 구독을 ‘해지 예약 취소’로 다시 살리지 않는다. 현재 서버는 사용자가 즉시 환불을 요청하는 API나 App Store/Play Store 구매 검증을 제공하지 않는다. 앱에서 유료 기능을 판매하는 방식은 출시 전 정책을 확인하고 별도 구현 범위를 정한다.

마이에서 제외하는 항목은 대시보드 기록 수, 최근 대화 표시 토글, 출근 시간, 카드 표시 간격, 체험 시각 변경, 데이터 초기화, 가짜 요금제 변경이다. `/v1/me/preferences`와 `/v1/me/summary`는 공개 계약에서 제거된 상태를 유지한다. 기존 비서 문맥은 보존하되 신규 습관 학습은 미구현이며 마이의 설정을 임의로 늘리지 않는다.

대시보드의 시간 범위 버튼(지금·3시간·5시간·하루)은 조회 범위를 바꾼다. 실제 시계나 실행 예약을 바꾸지 않는다. 체험용 시각·실패 데이터는 개발/시연 경로에 두고 실제 사용자 계정 설정에 포함하지 않는다.
