# 모리 화면 기획서

[Word 기획서 v0.3 내려받기](mori-screen-spec-v0.3.docx)

2026-09-30의 `poc` `aa3ca2f`와 `master` `1ba04c0`을 기준으로 정리했다. 39쪽에 화면 32개, 설명 요소 168개를 담았다. 캡처의 번호와 오른쪽 설명을 대조해 의미·진입 경로·클릭 동작·현재 범위를 검토한다. 의견은 `D02 5번`처럼 화면 ID와 요소 번호로 남길 수 있다.

| 화면 ID | 범위 |
| --- | --- |
| D01–D06 | 대시보드, 시간 범위와 시간대별 목록, 기록 |
| S01–S06 | 월·주·일 캘린더, 직접 등록·입력 피드백·상세 |
| C01–C04 | 대화 목록·결과 연결·정리·음성 |
| F01–F04 | 기능 목록·커스텀 정의·실행 조건·결과 |
| B01–B07 | 주차·뉴스·주가·메모·알림·문서 상세 |
| M01–M05 | 계정·이름 수정·테마·요금제·소셜 로그인 |

v0.3은 이전 Word 수정본의 한글 폰트 매핑과 줄 높이 보정을 유지하면서, 최신 마이 화면 5개를 다시 캡처했다. 체험 설정·대시보드 변경 설명을 제거하고 계정 API 연결, 무료와 관리자 승인 Pro, 실제 결제/취소 미지원 상태를 반영했다. Word를 렌더링한 39쪽 전체에서 한글 누락·겹침·페이지 넘침이 없는지 확인했다. Microsoft Word 앱 자체에서의 최종 열람은 별도 확인 대상이다.

마이 외 화면은 주로 로컬 PoC 동작이다. 실제 소셜 로그인 완료 상태·마이크 인식·기기 푸시는 이번 캡처에 포함하지 않았다. 화면의 예시 일정·주가·뉴스·습관 문맥을 실제 서비스 데이터로 해석하지 않는다. [백엔드의 현재 계약](../../back/screen-api-implementation-2026-09-30.md)과 함께 읽는다.

## 원본과 갱신 방법

- `source/build_spec.py`: 화면별 설명과 번호 위치, 문서 구성.
- `source/captures/`: 문서에 사용한 브라우저 캡처 32개.
- `source/screen-index.json`: 화면 ID·설명·좌표의 검토용 색인.
- `source/fix_word_layout.py`: 줄 높이·동아시아 폰트·페이지 구분의 Word 호환 보정.

Python 3의 python-docx·Pillow·lxml을 사용한다. 현재 번호 그리기 폰트 경로는 macOS의 Arial Bold이며 다른 OS에서는 해당 줄을 사용 가능한 숫자 폰트로 지정해야 한다. 생성은 다음 순서다.

```sh
python3 source/build_spec.py
python3 source/fix_word_layout.py
```

Word의 명시 폰트는 Malgun Gothic이다. 한글 폰트가 없는 headless 렌더러에서는 Noto Sans CJK KR 등 한글 지원 폰트를 준비하고 Fontconfig에서 Malgun Gothic의 대체 폰트로 매핑해야 한다. 폰트 누락으로 한글이 사라진 렌더링을 최종본으로 사용하지 않는다. 문서를 수정한 뒤에는 DOCX→페이지 이미지로 렌더링해 모든 페이지의 글자·캡처·표를 확인한다.

중간 DOCX·번호를 그린 임시 이미지·렌더링 PNG/PDF·Word 잠금 파일은 Git에서 제외한다. 최종 Word와 생성 소스·원본 캡처를 관리한다. 문서를 Word에서 직접 수정했다면 생성 소스에도 반영한 뒤 재생성해야 변경 내용이 유지된다.
