# PoC 화면 구현과 검증 기록

기준: `poc` `aa3ca2f`, 2026-09-30. HTML·JavaScript·SCSS PoC이며 제품 React 앱 완료 보고는 아니다.

## 구현한 화면

| 영역 | 구현한 내용 |
| --- | --- |
| 대시보드 | 현재 카드 캐러셀, 시간 버튼의 지금/3시간/5시간/24시간 탐색, 시간대별 가로 목록, 기록과 최근 대화 |
| 스케줄 | 월·주·일 보기, 직접 추가/편집, 날짜 선택, 자정을 넘는 일정과 겹침 표시 |
| 대화 | 검색·시기별 묶음·고정, 기존 대화 재개, 초안 보존, 채팅과 마이크 전환 |
| 기능 | 기본 기능 상세, 커스텀 정의 입력과 미리보기, 시간 유무/실행 결과 구분 |
| 기록 | 메모·문서·기능 결과의 통합 보관함과 유형 필터, 같은 기록의 상세 재진입 |
| 공통 UI | 여백·글자·카드/시트 규격, 선택 컨트롤 통일, 키보드 선택·포커스와 모션 감소 처리 |
| 마이 | 소셜 로그인/로그아웃, 실제 프로필·이름 편집, 시스템/라이트/다크, 무료·Pro 안내 |

시간 범위의 하루는 지금부터 24시간이다. 앞으로 예정된 카드를 펼쳐 볼 뿐 현재 시계·예약 상태·기능 실행을 변경하지 않는다. 표시 시작·약속 시작·수집 시작·알림 예정의 의미를 구분한다. 미래 검색 결과를 이미 생성된 것처럼 표시하지 않는다.

마이의 PoC용 개인화·대시보드 수정·시간·등급 전환·초기화 메뉴는 제거했다. 최신 범위는 [계정 정책](../product/account-scope-2026-09-30.md)이다. 대시보드 상단 하루 체험 기능은 로컬 PoC 시연용으로 남아 있다.

## 실제 API와 로컬 체험의 경계

마이의 프로필 조회/이름 수정, 테마, 요금제/이용권은 백엔드 API로 연결했다. 브라우저에는 소셜 토큰을 노출하지 않고 서버의 HttpOnly 세션으로 프록시한다. 변경 요청에는 Origin 검사를 적용한다. 로그인 전 테마는 브라우저에 저장하고 로그인 후 계정 테마를 사용한다.

다른 탭의 기록·일정·기능·대화는 아직 주로 브라우저 로컬 PoC다. 이번 백엔드 API 구현으로 전 화면이 자동 연동되는 것은 아니다. 기존 주차 테스트 경로와 새로운 도메인 API의 연결도 실제 계정으로 확인해야 한다. 로컬 체험 기록을 서버 계정으로 자동 이전하지 않는다.

음성은 브라우저 음성 인식과 텍스트 전환 체험이다. 현재 PoC의 전사 확인 흐름과 제품의 자동 전송 목표를 구분한다. OS 위젯·앱 종료 후 푸시·실시간 통화는 미구현이다. 뉴스·주가 예시는 실시간 데이터가 아니며 결제 버튼은 준비 중 상태다.

## 검증과 재현

```sh
npm run check
npm test
npm run build
npm run dev -- --host 127.0.0.1 --port 4173
```

51개 테스트, 정적 검사, 프로덕션 빌드가 통과했다. 테스트는 달력/시간 경계, 시간 범위 목록, 공유 선택 UI, 기록 합치기, 계정 프록시 계약 등을 포함한다. localhost:4173에서 주요 화면을 캡처했다. 최신 마이는 390px 모바일 폭에서 다시 캡처했다. 소셜 키가 없는 환경이므로 실제 네이버·카카오 로그인 왕복과 기기 마이크·푸시는 검증하지 않았다.

## 다음 연결 순서

1. 실제 소셜 계정의 프로필/이름/테마 왕복을 확인한다.
2. 메모·일정·보관함을 서버 데이터로 교체하고 revision 충돌·삭제 복원을 연결한다.
3. 대시보드를 서버 시간/그룹 응답으로 구성하고 로컬 예약 완료 연출을 서비스 상태와 분리한다.
4. 대화 목록·SSE·저장 결과 링크와 기능 정의/버전을 연결한다.
5. 새 채팅 계약을 실제 Hermes에서 검증한 뒤 예약 worker·기기 알림을 붙인다.
