# Front — 기능 중심 앱 화면과 상호작용

갱신일: 2026-10-06 · [전체 계획](../plan.md) · [제품 시나리오](../product/feature-dashboard-scenario-2026-09-29.md)

## 1. 목표와 현재 상태

최상위 탐색은 **대시보드 / 스케줄 / 대화 / 기능 / 마이**로 변경한다. 이전 오늘·캘린더·기억/보관함 탭 설계는 이 구성으로 대체한다. 메모/문서 결과를 보관함이라는 독립 탭으로 다시 추가하지 않고 대시보드 목록과 기능 상세에서 접근한다.

제품 프론트·앱·위젯은 사용자가 개발하고 AI는 요청한 작업과 API 계약을 지원한다. **React + TypeScript 반응형 웹을 React Native 앱의 WebView에서 재사용하는 방향으로 정한다.** 5탭·상세·대화는 웹, 권한·녹음·로그인 복귀·공유·앱 수명주기는 RN/네이티브, OS 위젯은 별도 확장이 맡는다. 휴대폰·태블릿 세로/가로와 브라우저 사용을 지원하고 기기 전용 기능에는 대체 동작을 제공한다.

당근의 공식 자료에서 확인한 네이티브·React 웹뷰·일부 Lynx 사용과 Mori의 RN 선택을 구분한다. [당근 조사](daangn-app-research-2026-10-02.md) · [앱/브리지 상세 설계](react-native-webview-plan.md) · [웹·앱 배포/버전 관리](../architecture/app-release-versioning.md).

현재 `poc` `3222659`에 5탭, 시간 범위별 가로 목록, 월·주·일 캘린더, 공통 선택 UI, 기록 보관함, 커스텀 기능 미리보기, 대화와 음성 전환을 구현했다. 주차 표시 설정과 모바일 문서 화면도 보완했다. 마이의 계정·테마·요금제 프록시는 실제 API에 연결했으며 나머지 탭은 로컬 PoC가 중심이다. 제품 React/RN 앱과 전 화면 서버 연결은 후속이다. [초기 구현·검증 기록](poc-validation-2026-09-30.md) · [10월 2일 보완](poc-ui-update-2026-10-02.md) · [Word 화면 기획서](../product/screen-spec/README.md).

PoC에 시기별 대화 묶음·검색·고정·이름 변경이 있고, 서버도 검색·제목 변경·고정·삭제를 지원한다. PoC 전체 대화의 서버 연결과 폴더 UI는 후속이다. 삭제된 대화의 복원과 영구 파기 API는 없다.

## 3. 대시보드 배치

```text
인사 / 오늘 날짜

지금 필요한 정보                  현재 시간 / 범위 선택
[ 주차 / 뉴스 / 주가 / 일정 / 시간 지정 내 기능 ] ↔
  제목·시간·상태·짧은 결과·상세 진입

기록과 정리
[ 메모 요약 ] [ 문서 결과 ] [ 시간 없는 내 기능 결과 ]
  저장/갱신 시각·출처 또는 파일·더 보기

최근 대화                          전체 보기 (선택안)

[ 모리에게 요청하기                     마이크 ]
대시보드    스케줄    대화    기능    마이
```

- 기본 지금 보기는 현재 표시 구간의 카드만 모은다. 오른쪽 시간 버튼에서 3시간·5시간·하루(현재부터 24시간)를 고르면 시간대별 가로 목록으로 펼친다. 조회 범위 선택은 시계·예약·기능 실행을 변경하지 않는다.
- 겹치는 카드의 순서와 표시 구간은 서버 계약을 따른다. 클라이언트와 서버가 각자 다른 우선순위를 계산하지 않는다.
- 현재 PoC는 수동 넘김·좌우 버튼·키보드 탐색을 제공한다. 자동 넘김은 제품 정책을 확정하기 전 적용하지 않는다.
- 항목이 하나면 불필요한 넘김을 없애고, 없으면 빈 캐러셀 공간 대신 간결한 안내/다음 예정 정보로 접는다. 다음 예정 노출 여부는 화면 검토로 결정한다.
- 시간 없는 결과는 유형별 레이아웃을 쓰되 동일한 여백·타이포그래피·메타데이터 위치를 유지한다. 시간 카드의 결과를 아래에 무조건 중복 표시하지 않는다.
- 세로 스크롤, 카드 가로 넘김, 대화 패널 드래그가 충돌하지 않게 영역을 분리한다. 탭/입력창이 키보드와 내용을 가리지 않게 한다.
- 조회는 저장 결과를 보여주며 화면을 열었다고 검색/추론을 재실행하지 않는다. 새로 실행은 명시적 동작으로 구분한다.

## 4. 카드와 상세 화면의 공통 규격

서버의 `template_key`/버전과 허용된 블록 데이터를 렌더링하는 방향이다. 임의 HTML/JS/CSS나 원격 생성 화면을 렌더링하지 않는다. 필드명은 설계 초안이며 실제 API 스키마와 합의해 확정한다.

| 요소 | 카드 | 상세 |
| --- | --- | --- |
| 제목·아이콘 | 짧은 제목, 작은 아이콘 | 같은 정체성, 기능 설정 진입 |
| 설명 | 존재할 때 짧게 | 존재할 때 전체 설명 |
| 시간 | 표시/예정 또는 데이터 기준 시각을 구분 | 반복·시간대·실행·알림·표시 구간을 필요한 수준으로 안내 |
| contents | 핵심 요약/수치/앞부분 | 텍스트·목록·체크리스트·표·이미지·파일 등 지원 블록 |
| work | 실행 상태나 행동 버튼 | 무엇을 하는 기능인지 쉬운 설명, 실행/수정/중지 |
| 상태 | 준비 중·갱신 중·완료·지연·실패·오래된 정보 | 원인/마지막 성공·수정·재시도 등 실제 지원 동작 |

title/description/시간/contents/work를 사용자에게 필수 폼으로 요구하지 않는다. title은 요청에서 제안하고 description/contents/시간은 생략 가능하다. 실행할 내용과 시간이 필요한 경우에만 질문한다. 필드가 없으면 여백과 구분선을 함께 접는다.

기본 기능은 동일한 공통 외곽 안에 전용 본문 컴포넌트를 넣는다. 커스텀 기능은 공통 템플릿을 사용한다. 미지원 템플릿 버전은 안전한 텍스트 요약과 업데이트 안내로 표시하고 화면 전체가 깨지지 않게 한다.

## 5. 기본 기능별 상세와 모션

| 기능 | 카드/상세 정보 | 전용 상호작용 방향 |
| --- | --- | --- |
| 주차 기록 | 층·구역·자리·기록 시각, 언제 표시되는지 | 위치를 또렷하게 강조하고 저장 완료 시 짧은 전환 |
| 뉴스 | 요약·주제·출처·수집 시각·실행 상태 | 항목 확장, 로딩/내용 전환; 수집 전 가짜 기사 표시 금지 |
| 주식 주가 | 종목/시장·통화·가격·기준 시각·지연 여부 | 값 갱신 강조; 실제 데이터 없는 차트/등락을 만들지 않음 |
| 메모 | 제목·본문·갱신 시각 | 부드러운 펼침·편집/저장 피드백 |
| 스케줄 | 제목·시간·장소·알림 | 달력/주/일 전환, 일정 추가/수정 결과 반영 |
| 알림 | 목표 시각·남은 시간·전달 상태 | 제품 전용 카운트다운·완료 전환, 취소/시간 변경 |

애니메이션은 상태 전환을 이해하게 돕는다. 마스코트가 기존 자산으로 있다면 입력/대기/완료에 활용하되 정보를 가리거나 긴 지연을 감추는 연출로 쓰지 않는다. 지속적으로 움직이는 여러 카드가 서로 경쟁하지 않도록 한다. 모션 감소 설정·스크린리더·글자 확대·충분한 대비/터치 영역을 지원한다.

카운트다운은 목표 시각 기준으로 계산한다. 앱 일시중지·재실행·기기 시각 변경 후 서버 값으로 보정한다. 숫자 0과 실제 알림 전달 완료는 다르며 앱이 닫힌 동안의 기기 알림은 네이티브/서버 계약으로 구현한다.

등록 완료 후 상세 이동은 현재 사용자가 해당 작업을 보고 있을 때 적용한다. 다른 화면으로 이동했거나 백그라운드라면 결과 카드/딥링크를 제공하며 뒤늦게 화면을 강제로 빼앗지 않는다.

## 6. 올라오는 채팅 패널과 마이크

### 텍스트

대시보드 입력을 선택하면 대화 패널이 아래에서 확장된다. 입력 초안·스크롤·키보드 상태를 보존하고 접으면 대시보드 위치로 돌아온다. 패널 닫기와 실행 취소를 같은 동작으로 가정하지 않는다. 다만 현재 API는 스트림 연결 종료 시 중단될 수 있으므로 연결 유지/취소/기록 복구를 명확하게 처리해야 한다.

### 음성

```text
마이크 선택 → 준비/권한 → 녹음·음성 반응 → 중지 → 전사
           → 대화 패널 확장 → 인식한 문장 표시·같은 채팅 경로로 전송
           → 진행 이벤트 → 답변/결과 → 다시 말하기 또는 텍스트 후속 입력
```

시리처럼 풍부한 빛/파형/전환 경험을 목표로 하되 녹음 중·전사 중·agent 실행 중을 구분한다. 녹음 취소·권한 거부·전사 실패에서 텍스트로 이어갈 수 있어야 한다. 매번 입력 방식을 바꿀 때 새 대화를 만들지 않는다. 같은 녹음의 이중 전송을 막고, 사용자가 말한 내용은 채팅에서 확인/정정할 수 있다.

전사 성공 후 자동 전달이 기본 시나리오다. 불확실한 전사나 실행에 필요한 정보가 빠진 경우에만 수정/질문을 제공한다. 실시간 음성 통화·항상 듣기·TTS는 이번 시나리오만으로 확정하지 않는다.

## 7. 실제 진행 상태 표시

현재 API의 SSE는 [채팅 계약](../back/chat-implementation-2026-09-29.md)을 따른다. fetch POST 스트림을 사용하고 네트워크 청크를 SSE 프레임으로 누적 파싱한다. 최종 답변은 현재 문장 전체로 전달한다.

| 현재 이벤트 | 화면 의미 |
| --- | --- |
| `run.accepted`, `runtime.connecting/ready` | 접수·연결/요청 확인 |
| `tool.started/returned` | 실제 도구 시작/결과 도착; returned만으로 성공 체크 표시 금지 |
| `action.started/completed` | 실제 주차·메모·일정·알림 목표 등 저장 작업/커밋 |
| `feature.selected`, `result.saved` | 선택한 정의 버전과 저장된 기능 결과/상세 참조 |
| `message.completed` | 최종 답변 말풍선 |
| `capability.unavailable` | 아직 지원하지 않는 예약 등 안내 |
| `run.completed/failed/interrupted` | 스피너 종료·결과/오류·복구 |

API 0.6.0에 기능 선택·결과 저장 이벤트와 기록의 result_refs가 추가됐다. PoC 채팅과 실제 SSE 연결은 후속이며, 별도 기능 조회/대시보드 갱신 이벤트가 모두 존재하는 것은 아니다. 서버 근거가 있는 단계만 표시한다. 모델 내부 추론이나 가짜 스킬 발견 문구를 만들지 않는다.

run ID/이벤트 순번/요청 키로 중복을 제거하고 연결 종료 시 실행 조회로 복구한다. HTTP 200을 완료로 해석하지 않는다. 장기 영속 작업 큐·앱 종료 후 실행 보장은 아직 미구현이다.

### 유휴 상태에서 다시 부탁할 때

DB에 저장된 대시보드·기능 목록은 에이전트가 쉬어도 조회한다. AI 요청만 runtime을 깨운다. 대기 화면에 실제 실행 상태를 보여주고 근거 없는 남은 초를 만들지 않는다. 개인 runtime·예약 유지의 상세는 [아키텍처](../architecture/plan.md#유휴-중지와-콜드-스타트)와 후속 계약을 따른다.

## 8. 스케줄·대화·기능·마이 상세

### 스케줄

달력/주/일 전환과 선택 날짜를 보존한다. 직접 추가는 채팅으로 보내지 않고 폼에서 처리한다. AI 등록과 직접 입력은 같은 일정 데이터를 사용하며 저장 후 즉시 같은 화면에 반영한다. 시간대·종일 일정·알림·삭제/수정 상태를 구분한다. 뉴스 예약을 모두 개인 약속 캘린더에 넣을지는 미정이며 초기에는 기능의 예약 설정과 분리한다.

### 대화

대화 목록 → 특정 대화 → 기존 메시지/기능 결과 → 후속 입력이다. 대시보드 패널과 동일한 대화 컴포넌트/상태 계약을 재사용한다. 대화 삭제 시 기능·예약·저장 결과까지 삭제하는 것으로 가정하지 않는다. 서버의 대화 삭제는 구현했으며 실행 중에는 409로 거부한다. 제품 UI 연결과 영구 파기 정책은 후속이다.

### 기능

기본 기능/내 기능을 구분하고 활성 여부·다음 실행·마지막 결과를 필요한 수준으로 표시한다. 새 기능 추가는 자연어 입력 중심이다. 시간형/텍스트형의 쉬운 예시와 선택적 필드 안내를 제공하되 개발 스키마를 폼으로 노출하지 않는다.

생성 결과는 공통 템플릿으로 미리보고 수정할 수 있다. 초안/실행 가능/예약 준비 중/활성/중지/실패를 구분한다. 아이콘 검색 실패는 기본 아이콘으로 대체한다. 기본 기능에만 전용 애니메이션을 제공하며 커스텀에는 공통 전환 효과를 적용한다.

### 마이

로그인·로그아웃, 사용자 정보·이름 수정, 시스템/라이트/다크 테마, 무료·Pro 요금제와 결제 관리만 배치한다. 대시보드 수정·출근 시간·기록 수·체험 등급 전환은 제거했다. 현재 Pro는 관리자 승인 방식이며 Free는 결제가 없다. 실제 결제·취소는 가격/주기/제공자가 정해질 때까지 준비 중이다. [최신 계정 범위](../product/account-scope-2026-09-30.md)를 우선한다.

## 9. OS 기능과 반응형 검증

앱 대시보드 캐러셀과 OS 위젯은 별개다. 홈 화면 위젯, 앱 종료 시 알림, 마이크 권한, 파일 저장/공유·딥링크는 네이티브 계층과 연결한다. 컨테이너는 React Native + WebView로 정하며 실제 기기에서 브리지·키보드·뒤로가기·수명주기를 먼저 검증한다. [구현 순서](react-native-webview-plan.md#9-개발-순서와-인수-기준)를 따른다.

OS 위젯은 사용자가 추가하며 갱신 시각에는 OS 제약이 있다. 08:30 표시 규칙을 저장했다고 위젯의 정각 갱신을 보장하지 않는다. 서버 결과와 표시 구간을 미리 준비하고 마지막 갱신 시각을 함께 보여준다. 앱 업데이트는 웹 release·native build·bridge·API 호환성을 확인하며, 새 native 기능은 스토어 앱 배포에 포함한다.

폰 세로/가로, 태블릿 세로/가로에서 같은 정보 우선순위를 유지한다. 가로에서 키보드/패널이 본문을 가리지 않게 하고 큰 화면은 여백·열 구성을 조정한다. 화면 너비 때문에 메뉴 종류나 기능 의미가 달라지지 않는다.

오프라인에는 마지막 데이터와 기준 시각을 표시한다. 계정 전환/로그아웃 시 이전 사용자의 결과·음성 임시 파일·대화 캐시를 정리한다. 외부 페이지에는 앱 브리지를 노출하지 않는다.

## 10. 변경 작업과 인수 기준

1. 5탭 IA와 공통 카드/상세 토큰·블록을 확정한다. 기본 6종과 커스텀 시간형/무시간형 목업을 비교한다.
2. 시간 카드 0/1/여러 개·겹침·수집 중·실패·오래된 결과와 시간 없는 목록을 검토한다.
3. 대시보드→채팅 패널→음성→텍스트→과거 대화 재개의 입력/스크롤/대화 ID 보존을 검증한다.
4. 기존 채팅 API를 먼저 연결하고 새 기능 계약 추가 시 실제 기능 조회/선택/결과 이벤트로 확장한다.
5. 주차 저장→다음 출근 표시, 09:00 뉴스, 메모, 일정 직접/AI 추가, 30분 알림 상세를 실제 데이터로 검증한다.
6. 커스텀 기능의 선택적 필드·아이콘 fallback·새 버전·중지·시간 없는 결과가 공통 UI 안에서 표시되는지 검증한다.
7. 실제 기기에서 알림 권한 거부·앱 종료·회전·모션 감소·스크린리더·글자 확대를 확인한다.

현재 PoC는 최근 대화 최대 2개, 최근 기록 최대 3개를 보여주며 마이에서 노출을 조정하지 않는다. 자동 넘김과 제품의 기본 채팅 재개 정책은 후속 검토다. 10월 2일 기준 56개 PoC 테스트·구문 검사·CSS 빌드가 통과했지만 실제 서버/기기 인수 검증을 대체하지 않는다. 이번 문서 변경에서 제품 프론트나 앱을 구현한 것은 아니다.

제품 구현은 F-09 공통 기반/브리지 검증 → B-18 웹 세션 연계 → F-10 실제 API 화면 연결 → A-06 배포/호환성 → F-11/B-19 음성·기기 기능 → A-07 출시 순서다. 첫 실제 동선은 소셜 로그인 → 주차 저장 → 대시보드 재조회 → 채팅/SSE로 잡는다.
