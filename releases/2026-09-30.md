1. 제품 정책: 마이의 계정·테마·요금제 범위와 기존 시나리오 정정.
2. 프론트: 5탭 동작, 시간대별 목록, 검증 범위와 다음 작업.
3. 백엔드: API 0.6.0 계약, 구현·미구현 구분과 화면별 연결.
4. 아키텍처: 현재 구현과 개인 Pod·예약 실행의 후속 범위.
5. 화면 기획서 소스: 32개 캡처, 요소 색인, 문서 생성·Word 보정 코드.
6. 화면 기획서 결과: Word v0.3과 읽는 방법·재생성 안내.
7. 전체 계획: 진행 현황·개발 순서와 이 변경 기록.

[Word 기획서 v0.3](../product/screen-spec/mori-screen-spec-v0.3.docx)은 39쪽, 화면 32개, 설명 요소 168개다. 최신 마이 화면 5개를 반영했고 렌더링한 39쪽을 모두 확인했다. Microsoft Word 앱 자체에서의 최종 열람은 별도 확인 대상이다.

## 검증과 다음 작업

- 백엔드: PostgreSQL 기반 테스트 185개, Ruff, OpenAPI 스냅샷 일치 검사 통과.
- PoC: 테스트 51개, JavaScript 구문 검사, SCSS 빌드 통과.
- 문서: Git 공백 검사, Word 전체 페이지 렌더링과 육안 검토 완료.
- 실제 Hermes 새 JSON 작업 계약·GPU/k3s 왕복, 운영 소셜 로그인, 전 화면 서버 데이터 연결은 다음 검증 대상이다.
- 예약 실행·cron 동기화·사전 기동 유지, 개인 Pod 자동 배정, 기기 푸시, 주가 제공자와 실제 결제/취소는 미구현이다.

무료에는 결제가 없고 현재 Pro는 관리자 승인 권한이다. 결제 화면 안내나 알림 목표 저장을 실제 결제 처리·기기 알림 전달 완료로 해석하지 않는다. 개발 순서는 [전체 계획](../plan.md)의 인수 기준을 따른다.
