## 독립 리뷰와 최종 재실행 결과

여러 차례 리뷰에서 발견한 결함을 고쳤고 마지막에는 세 에이전트가 실행 흐름, 데이터/문서, 계정/결제/런타임을 나눠 현재 소스와 회귀 검사를 다시 확인했다. 마지막 검토 범위에서 새 확정 P1/P2/P3 결함은 없었다. 모든 환경에서 결함이 없다는 보장은 아니다.

2026-11-03 master 커밋 전 실제 재실행 결과:

| 검증 | 결과 |
| --- | --- |
| 임시 PostgreSQL 기반 backend 전체 | **726개 통과**, 기존 외부 라이브러리 deprecation 경고 2건 |
| Hermes 전체 | **91개 통과·1개 skip·43 subtest 통과** |
| skip 사유 | 로컬 Trafilatura 미설치에 따른 기존 추출 검사 |
| DB | migration 왕복·모델/스키마 비교 통과, 임시 PostgreSQL 종료·삭제 |
| 정적/계약 | Ruff·포맷·OpenAPI 일치·uv.lock 오프라인 일치·diff 검사 통과 |
| Git | master 푸시 후 HEAD와 origin/master 일치, master 작업 폴더 clean |

이 plan 문서 갱신에서는 위 검증 기록과 source/OpenAPI를 확인하며 제품 테스트 전체를 다시 실행하지 않는다. 이전 과거 검증 수치 204·603·716 등은 해당 시점 이력이며 최신 합계에 중복 합산하지 않는다. 실제 제공자 HTTP는 제어한 transport로 대체했고 정상 원본 HWP/HWPX 전체·실제 Linux 자원 제한/이미지·GPU 모델·결제사·소셜·모바일·클러스터 인수를 끝냈다고 표시하지 않는다.

## 리뷰 과정에서 보완한 주요 경계

- 결제 취소·과거 주문 확인이 새 구독을 잘못 바꾸지 않도록 상태와 기간 연결을 검증했다.
- 채팅·예약·문서의 lease·generation·소유권·취소 상태를 결과 게시 전에 다시 확인한다. 지연된 예약은 원래 회차의 날짜·시간대로 메모를 선택한다.
- 뉴스 수동 갱신은 180초 기한을 두고 loading 고착을 복구하며 이전 성공 결과와 출처를 보존한다.
- 주가 snapshot은 오래된 응답의 덮어쓰기를 막고 비정상 미래 timestamp를 거부한다. 각 실행의 실제 조회 결과는 별도로 보존한다.
- DOCX 순서·중첩 표·콘텐츠 컨트롤·단순 필드 표시값·병합 셀을 처리하고 원본/편집 번호·잘림 계약을 유지한다. HWP 진입점과 HWPX run/구역 읽기도 보완했다.
- 날짜의 UTC 표현 범위, OAuth 비정상 응답·갱신 토큰, 기기명/검색어 NUL, 문서 JSON의 NUL·비유한수·직렬화 한계를 저장 전에 검증한다.
- 단순 복원으로 메모의 내용 저장 시각이 바뀌지 않고 알림 재시작의 시작 시각을 저장한다. 대화의 실제 활동 시각과 관리 수정 시각도 구분한다.

수정마다 재현 조건과 검사 범위를 남겼다.
