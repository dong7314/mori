# 2026-11-04 프론트 상세 계획·공식 조사 갱신

이 기록은 `plan`의 문서 변경이다. 제품 프론트 출시·새 앱 버전 발급·서버 배포 기록이 아니다. 화면 기준은 `poc 8fa4fe4`, 서버 기준은 `master 6285aba` / API 0.9.0으로 유지한다.

## 1. 요청과 확인한 현재 상태

사용자가 직접 프론트를 개발할 수 있도록 큰 01~12 단계를 실제 화면 작업으로 나누고, 웹/RN 역할·UI 컴포넌트·라이브러리·앱 버전/배포를 상세화했다. 원격 브랜치를 확인했으며 기준 PoC와 master의 신규 커밋은 없었다. PoC README 일부는 실제 대시보드와 달라 현재 소스·모듈·OpenAPI를 우선했다.

Ego의 격리 mobile preview에서 대시보드·기능 목록/새 기능·반복 option·일정 입력·마이를 읽기/탐색했다. 폼 저장·실제 계정/결제/모델/제공자 통합은 실행하지 않았다. 조사에 사용한 browser task는 종료했고 임시로 시작한 PoC 검사 서버도 종료했다.

## 4. 구체화한 Mori 선택

- React DOM/Vite 웹을 RN 주 WebView에서 사용한다. 기기 기능만 native 경계로 두며 RN JS OTA·Lynx·서비스별 MFE 플랫폼은 초기 제외한다.
- Stackflow 단일 탐색, React Aria 접근성 기반의 Mori 컴포넌트, CSS Modules/Sass 토큰, Query 서버 상태·RHF/Zod 폼·제한된 Zustand UI store를 기본안으로 검증한다. Motion과 화면 스택은 같은 요소 transform을 중복 제어하지 않는다.
- 주가 차트는 캔들 전용 라이브러리를 필요한 상세에서 로드하고 데이터 의미·접근성 대체와 라이선스/출처 요구를 보존한다.
- 라이브러리 관측값을 설치 조합으로 단정하지 않는다. TypeScript latest 7.0.2와 openapi-typescript 7.13.0의 peer ^5.x 차이를 확인해 초기 TS 5.9.3 후보와 실제 빌드 후 고정 절차를 적었다.
- 앱 표시 버전·플랫폼 build·웹 SHA/build ID·API v1/service0.9·bridge/capability·정책 revision은 각각 추적한다. 오래된 앱에는 호환 웹을 선택하고 필수 기능이 없을 때 fallback도 별도 검증·한 번만 시도한다.
- 메모리 초안의 탭/패널 보존과 프로세스 종료 뒤 영속 복구를 구분한다. 초기에는 저장 전 초안·녹음의 종료 후 복구를 보장하지 않으며 실제 보관분과 서버 run만 복원한다.

## 5. 아직 실행하지 않은 것과 다음 착수

58개 FE 작업과 10개 release 작업은 모두 계획/대기다. React/RN 프로젝트 생성, 패키지 설치, 실제 타입/웹·native 빌드, client-config·B-18 웹 세션, CI·서명·스토어·실기기 인수는 이번에 수행하지 않았다. backend 726개/Hermes 91개 검사는 11월 3일 기록이며 이번 계획의 프론트 검사 수로 사용하지 않는다.

첫 구현은 FE-01 웹 workspace·타입·공통 UI와 작은 상세다. FE-02에서 대시보드를 재현하고 FE-03에서 RN/WebView를 최소 검증한다. 01 첫 PR에 RN 완성까지 요구하지 않는다. 이어 B-18과 로그인→주차→대시보드→durable 채팅을 연결한다. 기기/제공자 없는 fixture 검사와 실제 연결 완료는 따로 기록한다.

## 6. 문서 검증

서브 에이전트가 산업 사례, 버전/릴리스, 실제 PoC 작업을 나누어 작성하고 교차 검토했다. 루트는 라이브러리 공식 문서·metadata와 컴포넌트 규격·상위 계획을 대조했다. 웹 첫 PR/RN 실험 범위, 현재 기능 카드 grid, 공통 경로/컴포넌트 이름, draft 복구 범위, fallback capability 검사 모호함을 수정했다.
