# Back — 구현 현황과 다음 개발 계획

갱신일: 2026-11-03 · [전체 계획](../plan.md) · [상세 구현·잔여 작업](implementation-status-2026-11-03.md) · [모바일 확장 계약](mobile-client-contracts.md)

## 1. 현재 기준과 완료의 의미

현재 기준은 `master` **6285aba**, API **0.9.0**, PostgreSQL migration **0017_news_refresh_deadline**이다. 누적 기능과 회귀 수정을 16개 커밋으로 나누어 원격 master에 반영했다. [고정 커밋의 기능 문서](https://github.com/dong7314/mori/blob/6285abac905b242442cceda103c63e18d8900ab3/backend/docs/poc-backend-0.9.md)와 [OpenAPI](https://github.com/dong7314/mori/blob/6285abac905b242442cceda103c63e18d8900ab3/backend/docs/openapi.json)가 현재 계약이다.

PoC의 화면 동작에 대응하는 서버 기능과 worker·manifest를 구현하고 로컬에서 검증했다. **PoC의 localStorage를 새 API로 교체하거나 제품 React/RN 화면을 구현한 상태는 아니다.** 실제 제공자 계정·GPU 모델·Harbor 이미지·k3s·모바일 기기 통합도 별도다. ‘코드 구현’, ‘로컬 검증’, ‘제품 화면 연결’, ‘운영 인수’를 구분한다.

2026-11-03 커밋 전 전체 검사에서 backend 726개, Hermes 91개와 subtest 43개가 통과했다. Hermes 1개는 로컬 Trafilatura 미설치로 건너뛰었고 backend 외부 라이브러리 deprecation 경고 2건은 남아 있다. 마이그레이션 왕복·모델 차이, Ruff·포맷·OpenAPI·uv.lock·diff 검사도 통과했다. 이 문서 갱신에서 제품 테스트를 새로 실행한 수치는 아니다.

9~10월의 [화면 API 0.7 기록](screen-api-implementation-2026-09-30.md), [주차·텍스트 문서 변경](parking-document-update-2026-10-02.md), [채팅 0.5 기록](chat-implementation-2026-09-29.md)은 당시의 이력이다. 그 문서의 ‘미구현’과 과거 migration 번호를 현재 상태로 사용하지 않는다.

이전의 ‘Hermes가 cron을 저장하고 Mori는 깨우기만 한다’는 안은 현재 구현으로 대체했다. 동일 예약을 Hermes cron에 다시 등록하지 않는다. 공용 gateway의 사용자 ID 확인만을 데이터 격리의 전부로 삼지 않으며, 사용자별 자식 프로세스와 HOME을 함께 분리한다.

## 4. 채팅과 기능 실행 규칙

일반 자연어 작업의 진입점은 채팅이다. 웹 검색용 공개 API를 다시 만들지 않는다. 화면에서 직접 편집하거나 결과를 조회하는 도메인 API는 계속 사용한다.

1. 사용자·대화·첨부 소유권과 서버가 정한 runtime을 검사한다.
2. 사용자 기능과 현재 설정을 문맥으로 전달한다. `feature_lookup`은 실제 전달한 최대 50개 ID 안에서 상태·상세만 조회한다.
3. 기능 실행은 선택한 버전과 `allowed_actions`에 묶는다. 기본 권한은 `reply`; 저장 작업은 사용자가 편집 API에서 명시적으로 허용한다.
4. 모델의 JSON 작업 제안은 서버가 다시 검증한다. 서로 다른 저장 2~4개 batch는 한 트랜잭션으로 처리하고 일부 저장을 성공으로 포장하지 않는다.
5. 외부 응답을 받은 뒤에도 상태·버전·권한을 다시 확인하고 결과와 완료 기록을 게시한다.
6. 연결이 끊겨도 실행은 이어가며 클라이언트는 같은 run의 상태/이벤트로 재접속한다. 새 실행 POST로 복구하지 않는다.

Mori의 `Feature`·`SkillVersion`이 현재 재사용 정의다. Hermes 로컬 `SKILL.md` 자동 생성·동기화나 전용 스킬 파일 저장소는 완료 항목이 아니며 현재 실행의 필수 전제도 아니다. 사용자 기능은 현재 버전의 work와 제한된 action 계약으로 실행한다.

## 5. 예약·런타임과 결제의 경계

예약은 Mori DB의 기능 schedule과 실행 회차에 저장한다. worker는 Hermes가 필요한 활성 사용자 기능과 AI 요약 뉴스에 한해 기본 120초 전부터 인증된 toolsets 조회로 배정 환경을 깨우고 실제 회차를 수행한다. 주가 수집·단순 표시·Web Push마다 Hermes를 깨우지 않는다. 단발·매일·평일과 IANA 시간대를 지원한다. DST의 없는 벽시각은 건너뛰고 중복 시각은 첫 발생을 사용한다. 늦은 재시도는 원래 `scheduled_at`과 시간대로 문맥을 만든다. 정시 완료나 외부 부수 효과의 무조건적인 정확히 한 번 실행은 보장하지 않는다.

무료 공용 프로필과 Pro 개인 PVC 사이의 자동 메모리 이사는 미구현이다. Pro `ready`는 Route 준비이며 Pod 상시 실행을 뜻하지 않는다. 구독 만료/관리자 승인 회수 후 서버가 이용권을 다시 검사하고 개인 환경을 회수한다. 기존 PVC 데이터는 보존한다.

Toss는 웹 자동결제다. 서버가 금액과 고객 키를 정하고 제공자 재조회로 승인 상태를 검증한다. 불확실한 주문은 `review`로 남겨 새 과금을 막는다. 기간 말 취소와 취소 철회는 구현했지만 즉시 환불 요청 API는 없다. 관리자 승인 권한과 유료 구독 권한은 별도로 유지한다. StoreKit/Google Play를 Toss 완료 API로 대신하지 않는다.

B-18 웹 세션과 client-config, B-19 기기/위젯 경로는 현재 OpenAPI에 없다. 프론트 착수에 필요한 세션 계약을 먼저 확정하고, 외부 환경 준비는 병행할 수 있다. 반복 개인 일정·자동 습관 학습·자유 아이콘 자산·실시간 체결·OCR·HWP 원본 편집 등은 첫 통합의 필수 API 누락과 구분해 별도 제품 범위로 결정한다.
